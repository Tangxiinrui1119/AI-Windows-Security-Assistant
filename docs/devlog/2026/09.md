### 今日学习
- 学习 NTFS：Windows 的文件系统，权限能力建立在它之上（NTFS ≠ ACL）

- 学习 Allow / Deny：为什么 Deny 常常「压过」Allow，以及 Deny 只针对具体权限、不是一票否决
- 学习用户组与组 SID：权限可以授予组，组也是安全主体

- 学习权限继承：父对象 → 子对象；Explicit ACE 与 Inherited ACE；关闭继承 ≠ 立即删除现有权限
- 学习 Effective Permissions：最终有效权限，以及判断五步法
- 完成综合实战例题推演（Project → Secret → password.txt：Read ✅ / Write ❌）

### 今日学习

- 纠正「Deny 永远优先」的死记法：按判断链一步一步推演
- 完成综合练习（secret.txt：Read ✅ / Write ✅ / Delete ❌）

### 今日实践
```powershell
icacls "$env:USERPROFILE\Desktop"          # 观察继承 ACE：(I)(OI)(CI)(F)
icacls "$env:USERPROFILE"                  # 对比：显式 ACE，没有 (I)
New-Item "$env:USERPROFILE\Desktop\acl-test.txt" -ItemType File
icacls "$env:USERPROFILE\Desktop\acl-test.txt"   # 文件上只有 (I)(F)，验证继承真的发生
icacls "$env:USERPROFILE\Desktop\acl-test2.txt" /grant "Everyone:(R)"   # 添加显式 Allow
icacls "$env:USERPROFILE\Desktop\acl-test2.txt" /deny "Everyone:(W)"    # 添加 Deny
```

### 今日疑问
- `OI/CI` 只是继承传播设置，不能单凭它证明后代当前已拥有该 ACE——已在实验中解答：新建文件后直接查看子对象 ACL 才是真正的验证。
