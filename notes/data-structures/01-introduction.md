# 1.1 学习数据结构与算法的意义

程序解决问题时通常有两个核心问题：

1. 数据怎样组织和保存？
2. 数据怎样被高效处理？

因此：

数据结构：
> 研究数据怎样组织，以及数据元素之间存在什么关系。

算法：
> 研究解决问题的具体步骤和方法。

数据结构和算法通常是相互联系的。

不同的数据结构，会直接影响：

- 查找效率
- 插入效率
- 删除效率
- 内存使用
- 算法实现难度

---

# 1.2 数据结构的基本概念

## 1.2.1 数据、数据元素和数据项 ★★

### 数据

能够被计算机识别、存储和处理的信息。

例如：

- 数字
- 字符
- 学生信息
- 图片
- 音频

---

### 数据元素

数据的基本单位。

例如：

一个学生信息表中：

张三：
- 姓名：张三
- 年龄：19
- 成绩：90

“张三这个学生”整体可以看作一个数据元素。

---

### 数据项

构成数据元素的更小单位。

例如：

- 姓名
- 年龄
- 成绩

都是数据项。

关系：

数据
↓
数据元素
↓
数据项

---

# 1.2.2 逻辑结构 ★★★

逻辑结构描述：

> 数据元素之间在逻辑上存在什么关系。

注意：

**逻辑结构不关心这些元素具体存储在什么内存地址。**

常见逻辑结构分为四类。

---

## 1. 集合结构 ★

元素之间除了属于同一个集合之外，没有明显的前后关系。

例如：

{A，B，C，D}

---

## 2. 线性结构 ★★★

元素之间存在一对一的逻辑关系。

例如：

A → B → C → D

对于中间元素：

- 有唯一直接前驱
- 有唯一直接后继

典型结构：

- 线性表
- 栈
- 队列
- 串

注意：

这里的“前驱”和“后继”是**逻辑关系**，不是内存地址关系。

---

## 3. 树形结构 ★★

元素之间是一对多关系。

例如：

        A
       / \
      B   C
     / \
    D   E

典型：

- 二叉树
- 文件目录结构

---

## 4. 图状结构 ★★

元素之间可以存在多对多关系。

典型：

- 城市交通网络
- 社交关系网络
- 计算机网络

---

# 1.2.3 存储结构 ★★★

存储结构描述：

> 数据实际怎样存放在计算机内存中。

一定区分：

逻辑结构：
> 元素之间是什么关系。

存储结构：
> 元素实际上怎么存。

常见存储结构：

---

## 1. 顺序存储 ★★★

数据存放在连续的内存空间中。

例如数组：

    int a[5];

特点：

- 地址连续
- 可以根据首地址和下标直接计算元素地址
- 支持随机访问

例如：

    arr[i]

本质上等价于：

    *(arr + i)

C/C++ 中指针加 1 会自动移动一个元素大小。

例如：

    int* p;

那么：

    p + 1

实际移动：

    sizeof(int)

个字节。

---

## 2. 链式存储 ★★★

节点可以存放在不连续的内存位置。

节点之间通过指针连接。

例如：

[10 | next] → [20 | next] → [30 | next]

特点：

- 不要求连续内存
- 不能直接根据下标计算第 i 个节点的地址
- 必须沿着 next 一个一个寻找

---

## 3. 索引存储 ★

额外建立索引，通过索引快速定位数据。

类似：

书本正文 + 目录。

---

## 4. 散列存储 ★

根据关键字通过某个函数直接计算存储位置。

以后学习哈希表时会详细学习。

---

# 逻辑结构与存储结构的关系 ★★★

非常重要：

**同一种逻辑结构可以有不同的存储实现。**

例如：

                 线性表
                   │
          ┌────────┴────────┐
          ↓                 ↓
        顺序表              链表
      顺序存储实现       链式存储实现

所以：

线性表 ≠ 顺序表  
线性表 ≠ 链表

线性表是一种逻辑结构。

顺序表和链表是线性表的两种实现方式。

---

# 1.2.4 抽象数据类型 ADT ★★

ADT：

Abstract Data Type

即：

抽象数据类型。

ADT主要描述：

1. 有什么数据
2. 数据之间有什么关系
3. 可以对数据进行什么操作

ADT重点关注：

> “能够做什么”

而不是：

> “底层具体怎么实现”

例如线性表规定可以进行：

- 初始化
- 插入
- 删除
- 查找
- 获取元素
- 遍历

但是并不规定：

插入到底通过：

- 数组移动元素实现

还是：

- 链表修改指针实现

所以可以理解为：

ADT：
> 功能和操作规范。

具体数据结构实现：
> 用代码真正完成这些功能。

# 1.3 算法

## 1.3.1 算法的定义

算法：

> 为解决某个问题而设计的一系列有限步骤。

---

## 算法的基本特性 ★★

一般包括：

### 1. 有穷性

算法必须在有限步骤后结束。

### 2. 确定性

每一步必须具有明确含义。

### 3. 可行性

每一步操作必须能够执行。

### 4. 输入

可以有零个或多个输入。

### 5. 输出

应产生一个或多个输出结果。

---

# 1.3.2 算法的描述

算法可以通过：

- 自然语言
- 流程图
- 伪代码
- C/C++程序

进行描述。

---

# 1.3.3 时间复杂度 ★★★

时间复杂度研究的不是：

> 程序实际运行了几秒。

而是：

> 当问题规模 n 增大时，算法执行次数增长有多快。

通常使用大 O 表示法。

常见时间复杂度：

O(1)
↓
O(log n)
↓
O(n)
↓
O(n log n)
↓
O(n²)
↓
O(n³)

一般越往下增长越快。

---

## O(1)

例如：

    x = a[3];

无论数组有 10 个元素还是 100 万个元素，访问次数基本不变。

所以：

O(1)

---

## O(n)

例如：

    for(int i = 0; i < n; i++)
        cout << a[i];

执行次数随着 n 线性增长。

所以：

O(n)

---

## O(n²)

例如：

    for(int i = 0; i < n; i++)
        for(int j = 0; j < n; j++)
            ...

执行：

n × n

次。

所以：

O(n²)

---

# 大 O 化简原则 ★★★

例如：

T(n) = 3n² + 5n + 100

当 n 很大时：

n² 项占主导。

因此：

O(n²)

一般：

1. 保留最高阶项
2. 去掉最高阶项系数
3. 忽略低阶项

例如：

5n³ + 2n² + 10n + 8

时间复杂度：

O(n³)

---

# 1.3.4 空间复杂度 ★★

空间复杂度表示：

> 当问题规模 n 增大时，算法额外使用的内存空间如何增长。

不是简单统计：

> 程序中写了多少变量。

例如：

    int a;
    int b;
    int c;

无论 n 多大，都只是固定几个变量。

所以：

O(1)

而：

    int a[n];

需要的内存随着 n 增大。

所以：

O(n)

空间复杂度可能涉及：

- 普通变量
- 数组
- 动态申请内存
- 辅助数据结构
- 递归调用栈

---

# 算法优化

算法优化常见目标：

- 减少时间复杂度
- 减少空间复杂度

例如：

O(n²)

优化到：

O(n log n)

通常是明显的效率提升。

但算法优化也不只考虑复杂度，还可能考虑：

- 常数开销
- 内存访问
- 缓存效率
- 代码复杂程度
- 实际运行环境
