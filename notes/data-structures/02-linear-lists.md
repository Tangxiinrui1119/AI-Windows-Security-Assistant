# 2.1 线性表的基本概念

## 2.1.1 线性表定义 ★★★

线性表：

> 由 n 个具有相同数据类型的数据元素组成的有限序列。

通常表示：

L = (a₁，a₂，a₃，...，aₙ)

例如：

(10，20，30，40)

---

## 线性表的逻辑关系 ★★★

例如：

A → B → C → D

对于中间元素：

- 有唯一直接前驱
- 有唯一直接后继

例如 B：

前驱：

A

后继：

C

注意：

这里描述的是：

**逻辑上的前后关系。**

不是说：

A 和 B 的内存地址必须连续。

---

## 空表

如果：

n = 0

则称为空线性表。

---

# 2.1.2 线性表的 ADT ★★

线性表作为逻辑结构，可以定义一系列操作。

---

## InitList

Initialize List

功能：

> 初始化一个线性表。

---

## DestroyList

Destroy List

功能：

> 销毁整个线性表，并释放相关资源。

---

## ClearList

Clear List

功能：

> 删除表中的所有元素，使线性表变为空表。

区别：

DestroyList：

表本身也被销毁。

ClearList：

表还存在，只是元素没了。

---

## ListEmpty

功能：

> 判断线性表是否为空。

---

## ListLength

功能：

> 返回线性表当前元素数量。

---

## GetElem

Get Element

功能：

> 根据指定位置获取元素。

例如：

“获取第 5 个元素”。

特点：

知道位置 → 找元素。

---

## LocateElem

Locate Element

功能：

> 根据元素值查找它的位置。

例如：

“查找值为 100 的元素在哪里”。

特点：

知道元素 → 找位置。

---

## ListInsert

功能：

> 在指定位置插入一个元素。

---

## ListDelete

功能：

> 删除指定位置的元素。

---

## Traverse

功能：

> 从头到尾依次访问线性表中的所有元素。

---

# 2.2 顺序表 ★★★

顺序表：

> 使用连续内存空间存储线性表元素。

可以理解为：

**顺序表底层主要采用数组思想。**

但：

顺序表 ≠ 单纯数组。

一个完整顺序表一般还需要记录：

- 数据
- 当前长度
- 最大容量

例如：

    struct SeqList
    {
        ElemType data[MAXSIZE];
        int length;
    };

其中：

data：

保存数据。

length：

保存当前实际元素数量。

MAXSIZE：

表示最大容量。

---

# ElemType ★★

ElemType 表示：

> 线性表中每一个元素的数据类型。

例如：

    typedef int ElemType;

那么：

    ElemType data[100];

实际上就是：

    int data[100];

如果定义为 Student：

那么顺序表就可以保存 Student 类型元素。

---

# 顺序表的地址计算 ★★★

教材常写：

LOC(aᵢ)
=
LOC(a₁) + (i - 1) × sizeof(ElemType)

表示：

> 根据第一个元素地址，计算第 i 个元素的地址。

例如：

a₁ 地址 = 1000

ElemType 为 int：

sizeof(int) = 4

那么：

a₂：

1000 + 1 × 4
=
1004

a₃：

1000 + 2 × 4
=
1008

---

## 与 C++ 指针的关系 ★★★

C++ 中：

    arr + i

本质上已经自动考虑元素大小。

例如：

    int* p;

执行：

    p + 1

地址不是简单 +1 字节。

而是增加：

    sizeof(int)

字节。

所以：

    *(arr + i)

等价于：

    arr[i]

这也是数组能够随机访问的原因。

---

# 顺序表为什么可以随机访问？ ★★★

因为：

1. 首地址已知
2. 每个元素大小相同
3. 内存地址连续

所以可以直接通过公式算出任意元素的位置。

因此按下标访问：

O(1)

---

# 顺序表按值查找

例如：

10 20 30 40 50

要查找：

40

如果没有其他辅助结构，一般需要从前向后逐个比较。

最坏情况：

检查 n 个元素。

所以：

O(n)

---

# 顺序表插入 ★★★

例如：

原来：

10 20 30 40

在 20 后插入 99：

10 20 99 30 40

由于顺序表要求连续存储：

原来的 30、40 必须向后移动。

一般需要：

> 从后向前移动。

原因：

防止覆盖还没有搬走的数据。

---

## 顺序表插入复杂度

最好情况：

在末尾插入。

O(1)

最坏情况：

在最前面插入。

需要移动 n 个元素。

O(n)

平均情况下：

O(n)

---

# 顺序表删除 ★★★

例如：

10 20 30 40

删除 20：

10 30 40

后面的：

30、40

都要向前移动。

---

## 顺序表删除复杂度

最好：

删除最后一个元素。

O(1)

最坏：

删除第一个元素。

O(n)

平均：

O(n)

---

# 顺序表优缺点 ★★★

优点：

- 内存连续
- 可以随机访问
- 根据下标访问 O(1)
- 不需要额外指针空间

缺点：

- 插入时可能移动大量元素
- 删除时可能移动大量元素
- 需要连续内存空间
- 固定数组情况下容量有限

---

# 2.3 链式存储

链表：

> 使用节点保存数据，节点之间通过指针建立逻辑关系。

节点实际地址可以不连续。

例如：

地址可能是：

A：1000  
B：8000  
C：3200

但仍然可以形成：

A → B → C

因为：

A.next 保存 B 的地址。

B.next 保存 C 的地址。

---

# 2.3.1 单链表 ★★★

一个单链表节点通常包括：

1. 数据域
2. 指针域

例如：

[data | next]

C++：

    struct Node
    {
        ElemType data;
        Node* next;
    };

---

# data 和 next

data：

> 保存当前节点的数据。

next：

> 保存下一个节点的地址。

---

# head ★★★

head：

> 指向链表起始位置的指针。

例如：

head
 ↓
[10 | •] → [20 | •] → [30 | nullptr]

如果没有头节点：

head 一般直接指向第一个数据节点。

---

# 头节点 ★★

有些链表会增加一个不保存有效数据的头节点。

例如：

head
 ↓
[头节点] → [10] → [20] → [30]

头节点主要作用：

> 让插入、删除等操作更加统一。

一定注意：

头指针 head 和头节点不是一回事。

head：

是一个指针变量。

头节点：

是一个真正的 Node 节点。

---

# p->data 为什么等于 (*p).data ★★★

假设：

    Node* p;

说明：

p 保存的是：

> 一个 Node 节点的地址。

执行：

    *p

表示：

> 找到 p 所指向的完整 Node 对象。

而一个 Node 内部还有：

- data
- next

所以：

    (*p).data

表示：

> 找到 p 所指向的节点，再读取里面的 data。

C++提供简写：

    p->data

因此：

    p->data

等价于：

    (*p).data

同理：

    p->next

等价于：

    (*p).next

---

# 单链表遍历 ★★★

最核心的动作：

    p = p->next;

含义：

> 让 p 从当前节点移动到下一个节点。

例如：

开始：

p
↓
A → B → C

执行：

    p = p->next;

之后：

    p
    ↓
A → B → C

不断执行即可遍历链表。

---

# 为什么链表不能随机访问？ ★★★

数组中：

第 i 个元素地址可以通过：

首地址 + i × 元素大小

直接计算。

但链表节点地址不连续。

例如：

A地址：1000  
B地址：8000  
C地址：3200

仅知道 A 地址：

无法通过数学公式推出 B、C 在哪里。

只能：

A
↓ 查看 next
B
↓ 查看 next
C

所以访问第 i 个节点：

通常为：

O(n)

---

# 单链表插入 ★★★

假设：

A → B

想在 A 和 B 中插入 X：

A → X → B

如果 p 指向 A，s 指向新节点：

正确思想：

    s->next = p->next;
    p->next = s;

第一步：

让 X 指向原来的 B。

第二步：

让 A 指向 X。

结果：

A → X → B

注意：

链表插入时指针修改顺序非常重要。

---

# 单链表删除 ★★★

原来：

A → B → C

删除 B：

只需要让：

A → C

例如 p 指向 A：

    Node* q = p->next;

    p->next = q->next;

    delete q;

其中：

q：

临时保存要删除节点的地址。

delete：

释放节点占用的动态内存。

---

# 链表插入删除复杂度 ★★★

如果已经知道操作位置：

插入：

O(1)

删除：

O(1)

因为只需要修改固定数量的指针。

但如果需要先从链表头寻找目标位置：

查找：

O(n)

因此整个过程可能仍然为：

O(n)

一定注意：

“链表插入删除 O(1)”

成立的前提通常是：

> 已经找到对应节点位置。

---

# 头插法 ★★

头插法：

> 每次把新节点插入链表最前面。

假设输入：

1 2 3

第一次：

1

第二次：

2 → 1

第三次：

3 → 2 → 1

最后得到：

3 → 2 → 1

所以：

> 头插法会使建立后的链表顺序与输入顺序相反。

---

# 尾插法 ★★

尾插法：

> 每次把新节点插入链表末尾。

输入：

1 2 3

结果：

1 → 2 → 3

所以：

尾插法保持原输入顺序。

---

# 单向循环链表 ★★

普通单链表：

A → B → C → nullptr

最后一个节点的 next：

nullptr

单向循环链表：

A → B → C
↑       ↓
└───────┘

最后一个节点的 next：

重新指向第一个节点。

如果：

head 指向第一个节点 A。

那么：

    C->next = head;

注意：

不是“指向 head 这个指针变量”。

而是：

> C 的 next 保存与 head 相同的节点地址。

因此整个链表形成循环。

---

# 2.3.2 双向链表 ★★★

单链表：

[data | next]

只能直接找到：

下一个节点。

双向链表：

[prior | data | next]

其中：

prior：

指向前一个节点。

next：

指向后一个节点。

---

## 双向链表结构

例如：

A ⇄ B ⇄ C

如果 p 指向 B：

    p->prior

可以找到 A。

    p->next

可以找到 C。

---

## 双向链表节点

    struct Node
    {
        ElemType data;
        Node* prior;
        Node* next;
    };

---

# 双向链表插入

例如：

A ⇄ B

中间插入 X：

A ⇄ X ⇄ B

需要同时维护：

- X 和 A 的关系
- X 和 B 的关系
- A 和 X 的关系
- B 和 X 的关系

核心思想：

> 双向链表的插入删除需要同时维护前后两个方向的指针。

建议通过画图理解，不要死背代码。

---

# 顺序表 vs 链表 ★★★

| 对比 | 顺序表 | 链表 |
|---|---|---|
| 逻辑结构 | 线性 | 线性 |
| 内存 | 连续 | 可以不连续 |
| 关系表示 | 内存位置 | 指针 |
| 按位置访问 | O(1) | O(n) |
| 查找指定位置 | 快 | 需要遍历 |
| 插入 | 通常 O(n) | 已知位置时 O(1) |
| 删除 | 通常 O(n) | 已知位置时 O(1) |
| 额外指针空间 | 不需要 | 需要 |
| 大小变化 | 相对不灵活 | 灵活 |

一句话理解：

顺序表：

> 用连续内存的位置关系表示元素顺序。

链表：

> 用指针表示元素之间的顺序关系。

---

# 顺序表不能简单等于数组 ★★

可以把顺序表理解成：

数组
+
当前长度
+
线性表操作

例如：

数组：

    int arr[100];

只能说明：

有一块能存 100 个 int 的空间。

顺序表通常还需要：

    length

表示当前真正有多少个有效元素。

例如：

MAXSIZE = 100

length = 5

表示：

最多能放 100 个。

目前只有 5 个有效元素。

---

# 第2章最重要的指针关系 ★★★

## 1.

    Node* p;

表示：

p 是指向 Node 的指针。

---

## 2.

    *p

表示：

p 所指向的完整 Node 对象。

---

## 3.

    p->data

等价于：

    (*p).data

表示访问当前节点中的 data。

---

## 4.

    p->next

表示：

当前节点中保存的下一个节点地址。

---

## 5.

    p = p->next;

表示：

让 p 移动到下一个节点。

这是遍历链表最核心的操作。

---

# 第2章核心理解 ★★★

一定不要混淆三个概念：

线性表：
> 逻辑结构。

顺序表：
> 用连续内存实现线性表。

链表：
> 用节点和指针实现线性表。

它们的关系：

                    线性表
                （逻辑结构）
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
        顺序表                    链表
          │                       │
       连续内存                可不连续
          │                       │
      数组思想                 指针思想
          │                       │
  直接计算元素地址          顺着 next 找地址
          │                       │
     访问 O(1)               访问 O(n)
          │                       │
 插删需要移动元素         已知位置后修改指针
