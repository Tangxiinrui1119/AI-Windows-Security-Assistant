## 3.1 使用点对点信道的数据链路层

### 3.1.1 数据链路和帧（PDF 2–8页）

数据链路层位于网络层与物理层之间。主机、路由器、交换机都需要相应的链路层功能：主机处理完整协议栈，路由器逐跳处理到网络层，普通二层交换机处理到数据链路层。一条端到端路径可能经过多种链路，每段可以使用不同协议。

| 概念 | 含义 | 注意 |
|---|---|---|
| 链路 link | 相邻结点之间的一段物理线路，中间没有其他交换结点 | 只是整条通信路径的一部分 |
| 数据链路 data link | 链路加上控制传输所需的协议硬件、软件 | 常由适配器实现 |
| 帧 frame | 数据链路层的协议数据单元 | 网络层的 IP 数据报被装入帧中 |
| 适配器 / NIC / 网卡 | 计算机连接网络的接口设备 | 通常包含物理层和链路层功能 |

发送端把 IP 数据报封装成帧，物理层把帧变成比特流；接收端检查帧并取出数据报。所谓两个对等链路层之间的“数字管道”，是隐藏物理传输细节后的抽象。

两种信道：**点对点信道**是一对一；**广播信道**是一对多共享媒体，必须协调各站的发送。

### 3.1.2 三个基本问题（PDF 9–22页）

#### 一、封装成帧

`帧 = 首部 + 数据部分 + 尾部`。首尾包含帧定界信息及协议控制信息。最大传送单元 **MTU** 限制的是**帧的数据部分**，不是整个帧长。

课件用 ASCII 控制字符举例：SOH 表示首部开始，EOT 表示传输结束；定界不完整的帧应丢弃。具体协议有自己的定界方式，不能把 SOH/EOT 当作所有帧通用格式。

#### 二、透明传输

数据中若恰好出现与定界符相同的代码，接收端不能把它当成边界。透明传输要求协议允许任意数据内容通过，用户无需避开某些字符。

**字节填充**：发送端在数据中的 SOH、EOT 前插入 ESC；数据本身的 ESC 也需要再加一个 ESC。接收端删除所插入的转义字符，还原原始数据。

示意：原始数据 `SOH ESC EOT`，转义后为 `ESC SOH ESC ESC ESC EOT`，外面另加真正的帧定界符。

> 理解补充：透明性解决“内容会不会被误认为控制信息”；它本身不保证传输中不会发生比特差错。

#### 三、差错检测与 CRC

传输可能使 0 变 1 或 1 变 0。误码率：`BER = 错误比特数 / 传输比特总数`，与信噪比有关。课件主要介绍循环冗余检验 **CRC**。

设数据 M 有 k 位，生成多项式对应的除数 P 有 n+1 位：

1. 在 M 后补 n 个 0，得到 `M × 2^n`。
2. 对 P 作模2除法，取 n 位余数 R（不足 n 位补前导0）。
3. 发送 `T = M × 2^n ⊕ R`，即 M 后拼接 R。
4. 接收端用相同 P 除收到的 T：余数非0则检出差错；为0则通过该项检查。

**模2运算**：加减都是逐位异或，不进位、不借位。如 `0101 ⊕ 0011 = 0110`；模2乘法的部分积也用异或累加，如 `1011 × 101 = 100111`。

课件例：`M=101001，k=6，P=1101，n=3`。

```text
补零：101001000
模2除以1101：商110101，余数001
发送：101001001
接收端用1101检验该发送串，余数为000
```

`P=1101` 对应 `P(x)=x^3+x^2+1`。课件列出的常用多项式：

- CRC-16：`x^16 + x^15 + x^2 + 1`。
- CRC-CCITT：`x^16 + x^12 + x^5 + 1`。
- CRC-32：`x^32+x^26+x^23+x^22+x^16+x^12+x^11+x^10+x^8+x^7+x^5+x^4+x^2+x+1`。

| 易混概念 | 正确区分 |
|---|---|
| CRC 与 FCS | CRC 是检错方法；FCS 是帧检验序列字段，CRC 是产生它的方法之一 |
| 检错与纠错 | CRC 能发现大量差错，不能指出具体哪位错，也不自动修正 |
| 检验通过与绝对无错 | 仍可能漏检；“无差错接受”是概率极高的判断 |
| 无比特差错与可靠传输 | 帧还可能丢失、重复、失序；可靠传输需序号、确认、重传等机制 |

## 3.2 点对点协议 PPP

### 3.2.1 PPP 协议的特点（PDF 23–26页）

PPP（Point-to-Point Protocol）用于点对点链路，课件以用户接入 ISP 为例。设计首要要求是**简单**。

应满足：封装成帧、透明传输、支持多种网络层协议和多种链路、差错检测、检测连接状态、规定 MTU、网络层地址协商、数据压缩协商。

课件所列不需要的功能：纠错、流量控制、帧序号、多点线路支持，以及单工/半双工链路支持。PPP 检出坏帧后丢弃，不提供基于帧序号和确认的可靠交付。

三部分组成：

| 组成 | 作用 |
|---|---|
| 封装方法 | 把 IP 数据报等封装到串行链路 |
| LCP：链路控制协议 | 建立、配置、测试、终止数据链路 |
| NCP：网络控制协议族 | 为不同网络层协议分别协商配置；不是仅一个协议 |

### 3.2.2 PPP 协议的帧格式（PDF 27–30页）

课件基本格式如下（不讨论协商压缩）：

| 字段 | 长度 | 值或作用 |
|---|---|---|
| F | 1字节 | 0x7E，即01111110，帧标志 |
| A | 1字节 | 0xFF，点对点场景不承担普通目的寻址作用 |
| C | 1字节 | 0x03 |
| 协议 | 2字节 | 0x0021：IPv4；0x8021：IP控制协议；0xC021：LCP |
| 信息 | 默认不超过1500字节 | 网络层数据或控制信息 |
| FCS | 2字节 | 帧检验序列 |
| F | 1字节 | 0x7E |

PPP 是面向字节的协议，帧长是整数字节。实现透明传输的方法随链路传输方式变化：

| 方式 | 处理 | 课件示例 |
|---|---|---|
| 异步传输 | 字符填充，以0x7D转义并改变后续字符 | 7E→7D 5E；7D→7D 5D；03→7D 23 |
| 同步传输，如SONET/SDH | 零比特填充：内容中每遇连续5个1就插入0，接收端删除该0 | 01111110→011111010 |

PPP 不使用序号、确认的理由：链路差错较少；链路可靠也不能确保整个 IP 网络可靠；FCS 足以承担此处的检错任务。

### 3.2.3 PPP 协议的工作状态（PDF 31–32页）

```text
链路静止 → 物理连接建立 → 链路建立（LCP协商）
→ 鉴别（若需要） → 网络层协议配置（NCP） → 链路打开
→ 结束网络层配置 → 链路终止（LCP） → 物理连接释放 → 静止
```

配置或鉴别失败会走终止过程。课件拨号例中，NCP 配置临时 IP 地址，结束时释放；具体接入方式和地址分配策略由实现决定。

## 3.3 使用广播信道的数据链路层

### 3.3.1 局域网的数据链路层（PDF 33–38页）

局域网通常属于一个单位，地理范围和站点数有限；便于共享资源、扩展和调整，提高可用性。课件展示总线、环形、星形拓扑及相应传输媒体。

共享媒体的协调方法：

- 静态划分：频分、时分、波分、码分复用。
- 动态接入：随机接入（可能碰撞）与受控接入（令牌、轮询等）。

以太网两项历史标准：DIX Ethernet V2（1982）和 IEEE 802.3（1983）。两者相近但并非完全相同。IEEE 将链路层分为 **LLC（逻辑链路控制）** 与 **MAC（媒体接入控制）**；MAC 处理媒体接入，LLC 与具体媒体无关。课件以常用 Ethernet V2 为主，通常不再展开 LLC。

网卡负责串并行转换、缓存、配合设备驱动、实现以太网协议。IP 地址属于网络层配置，MAC 标识链路接口。

### 3.3.2 CSMA/CD 协议（PDF 39–53页）

早期以太网共享一根总线，信号可被所有站听到，靠目的 MAC 地址选择接收者。多个站同时发送会碰撞。其交付方式是无连接、尽最大努力：不编号、不要求确认，坏帧丢弃，高层决定是否重传。

课件还介绍传统10 Mbit/s以太网的曼彻斯特编码：便于提取同步信息，代价是需要更高的频带宽度；不能推广为所有高速以太网均使用该编码。

**CSMA/CD = 载波监听多点接入 / 碰撞检测**：

1. 发送前监听；忙则等待。
2. 满足空闲间隔后发送，同时继续检测碰撞。
3. 遇碰撞立即停止发送数据，并发送人为干扰信号，使相关站知道碰撞。
4. 用截断二进制指数退避算法等待随机时间，之后重新监听、重试。

**先听后发仍会碰撞**：信号传播有时延，远端可能尚未听见发送信号便开始发送。设最大单程端到端传播时延为 τ，最迟约 `2τ` 才能知道是否碰撞，这个窗口称为**争用期 / 碰撞窗口**。

| 量 | 公式 | 决定因素 |
|---|---|---|
| 发送时延 T₀ | `L/C` | 帧长L、发送速率C |
| 单程传播时延 τ | `d/v` | 距离d、媒体传播速度v |
| 争用期 | `2τ` | 最大往返传播时延 |
| 检出碰撞所需最短发送长度 | `L_min ≥ 2τC` | 发送尚未结束时必须能听到碰撞 |

10 Mbit/s传统以太网的争用期为 **512 bit时间 = 51.2 μs**，对应 **64字节最短有效MAC帧**。帧若过短，发送者可能发完后才听到碰撞。帧间最小间隔为 **96 bit时间 = 9.6 μs**。

课件推算：若传播速率 `v≈2×10^8 m/s`，τ=25.6 μs，则仅按传播时间估计距离约5.12 km。这是简化估计，不能据此认为任意实际以太网布线都支持5 km；设备、线缆标准还有额外限制。

截断二进制指数退避：设重传次数为 i，`k=min(i,10)`；从 `0…2^k−1` 中随机取整数 r，退避时间 `r×2τ`。第1次为{0,1}，第2次为{0,1,2,3}。课件规定重传达16次仍失败则放弃并向高层报告。

**使用CSMA/CD的共享以太网只能半双工**；现代交换式全双工链路没有共享媒体碰撞，不使用CSMA/CD。

### 3.3.3 使用集线器的星形拓扑（PDF 53–57页）

10BASE-T：10表示10 Mbit/s，BASE表示基带，T表示双绞线。使用两对双绞线和RJ-45，课件给出的主机到集线器距离不超过100 m。

集线器是多接口转发器，工作在**物理层**。外观是星形，**逻辑仍为共享总线**，共享带宽和碰撞域，仍使用CSMA/CD。优点是便于增加站点、连接网段、隔离个别故障并显示运行情况。

### 3.3.4 以太网的信道利用率（PDF 58–60页）

碰撞与争用消耗信道，实际利用率达不到100%。设 `T₀=L/C`，`a=τ/T₀=τC/L`。a越小，传播延迟相对越小，利用率越高。

课件在无碰撞且总线空闲就立即调度发送的**理想化模型**下：

`S_max = T₀/(T₀+τ) = 1/(1+a)`。

它不是实际CSMA/CD在任意负载下的通用吞吐公式。固定速率时应限制距离、避免帧过短。课件提到“利用率约30%已重载”，应理解为共享争用式以太网背景，不能套用到现代交换机端口。

### 3.3.5 以太网的 MAC 层（PDF 61–70页）

#### 一、MAC 地址

常用MAC地址48位，即6字节。课件模型为：前24位组织唯一标识符OUI由IEEE分配，后24位由厂商分配。地址标识**接口/适配器**，并非主机的地理位置；多个网卡可以有多个MAC。

第一字节的最低位 I/G：0为单站，1为组地址。次低位 G/L（也常写U/L）：0为全球管理，1为本地管理。全48位为1，即 `FF:FF:FF:FF:FF:FF`，是广播目的地址。

网卡识别发往自己的单播、广播，以及配置接收的多播。广播和多播地址用于目的地址。混杂模式会接收接口所能听到的其他帧；它并不让交换机自动把所有端口的流量送来。

> 补充：MAC可以采用本地管理或软件配置；“固化在ROM”描述的是课件中的传统硬件地址模型，不能推导出MAC永不可更改。

#### 二、Ethernet V2 MAC 帧

| 字段 | 字节数 | 作用 |
|---|---:|---|
| 目的地址 | 6 | 接收接口或组 |
| 源地址 | 6 | 发送接口 |
| 类型 | 2 | 指明数据部分的上层协议 |
| 数据及必要填充 | 46–1500 | 不足46字节需填充；上限通常为MTU |
| FCS | 4 | CRC检错 |

MAC帧长度 `6+6+2+(46…1500)+4 = 64…1518字节`。物理层发送前还加7字节前同步码和1字节帧开始定界符；**这8字节不计入上述MAC帧长**。帧间间隔也不是帧字段。

无效帧包括：非整数字节、FCS检验失败、数据字段长度不合法。以太网丢弃无效帧，不负责确认重传。

V2的两字节字段表示类型；IEEE 802.3相应位置可表示长度，数据内包含LLC。课件用0x0600区分两者。

> 精确边界补充：长度值为0…1500，类型值从1536（0x0600）起；1501…1535不是普通合法长度，不能简单把所有小于0x0600的值都当作有效长度。

## 3.4 扩展的以太网

### 3.4.1 在物理层扩展以太网（PDF 71–72页）

可采用光纤与光纤调制解调器延伸链路，或级联集线器扩展覆盖。**碰撞域**是某站发送会与其他站发生碰撞的范围。

集线器把多个碰撞域合为更大的一个：覆盖扩大，但总吞吐量并未随站点数增加，碰撞风险上升，且不能直接用普通集线器互连不同速率的网段。扩展仍须满足时延和标准限制。

### 3.4.2 在数据链路层扩展以太网（PDF 73–87页）

网桥、交换机按目的MAC转发或过滤。交换机本质上是多端口网桥，通常用专用芯片转发，可同时连接多对端口，端口有缓存、可支持不同速率，常用全双工。

| 比较 | 集线器 | 二层交换机（未划分VLAN） |
|---|---|---|
| 工作层 | 物理层 | 数据链路层 |
| 转发依据 | 比特再生，不查MAC | 目的MAC及交换表 |
| 带宽 | N个用户共享B，平均约B/N | 课件理想模型每端口独享B，总容量约N×B |
| 碰撞域 | 所有端口属于同一碰撞域 | 每端口隔离；全双工连接不发生碰撞 |
| 广播域 | 不隔离 | 默认也不隔离 |

上表N×B是课件的端口容量模型，实际吞吐还受交换容量、端口竞争等约束。

交换方式：**存储转发**先收完整帧，可检错、缓存及速率匹配；**直通交换**收到目的MAC就开始转发，延迟小，但可能传播坏帧。

#### 自学习：学源地址，查目的地址

1. 收到帧，记录或更新 `(源MAC，进入端口，有效时间)`。
2. 查目的MAC：已知且对应另一端口，仅从该端口转发。
3. 未知目的地址，向除进入端口之外的相关端口泛洪。
4. 若目的地址仍在进入端口方向，过滤该帧。
5. 老化删除过期项目，适应主机移动、更换网卡等情况。

课件例：A从端口1发给未知的B，先学 `A→1` 再泛洪；B从端口3回答，学 `B→3`，并将回答单独转发到端口1。只有作为**源地址出现**才会被学习，不能因泛洪到B就认为已学到B。

双交换机例（PDF 80–81页）：S1端口1接A、端口2接C；S2端口1接E；二者端口5互连。依次A→B、C→E、E→A后：S1学到A→1、C→2、E→5；S2学到A→5、C→5、E→1。

冗余链路可能形成环路，引发重复帧、地址学习混乱和广播风暴。**STP生成树协议（IEEE 802.1D）**在逻辑上阻断部分链路，保留无环树状转发结构，无须拆掉实际布线。

### 3.4.3 虚拟局域网 VLAN（PDF 87–95页）

广播域是一次广播能到达的设备范围。仅换成交换机仍可能广播过多、难以隔离部门、管理困难。**VLAN**是与物理位置无关、按共同需求组成的逻辑局域网组；它是一种服务，并非全新物理网络。

每个VLAN形成独立广播域。课件中B1属于VLAN2，其广播由B2、B3收到，不传播到VLAN1、VLAN3。优点：改善性能、管理、成本和安全隔离。

| 划分依据 | 特点 | 代价或限制 |
|---|---|---|
| 交换机端口 | 最简单、最常用 | 移动到不同端口需调整配置 |
| 网卡MAC | 设备移动时可保留分组 | 维护MAC列表，换网卡需更新 |
| 协议类型 | 按帧类型分组，如IP、IPX | 按协议规则管理 |
| IP子网 | 按源IP及子网归属分组 | 需相应识别能力 |
| 高层应用或服务 | 按更高层需求分组 | 取决于设备支持 |

**802.1Q带标记帧**：在源MAC后、原类型/长度字段前插入4字节标记：2字节标记类型0x8100，加2字节TCI。课件TCI分为3位优先级、1位CFI、12位VLAN ID。最大MAC帧由1518增至1522字节；课件图中最小数据部分可为42字节，对应整体最小帧长仍为64。

> 数值补充：12位有4096种编码，常规可配置VID为1…4094；0和4095有特殊用途，因此“4096种编码”不等于4096个普通可用VLAN。CFI是课件沿用的字段名称，现代以太网语境常称DEI。

## 3.5 高速以太网

### 3.5.1 100BASE-T 以太网（PDF 96–97页）

速率达到或超过100 Mbit/s称高速以太网。100BASE-T也叫快速以太网，IEEE 802.3u。保持以太网帧格式和64字节最小帧长；半双工使用CSMA/CD，全双工不使用。

从10提高到100 Mbit/s后，512 bit争用期由51.2变成5.12 μs；96 bit帧间隔由9.6变成0.96 μs。保持最短帧时，必须相应限制传播时延。

| 标准 | 课件媒体 | 课件网段最大长度 |
|---|---|---:|
| 100BASE-TX | 两对5类UTP或STP | 100 m |
| 100BASE-T4 | 四对3类或5类UTP | 100 m |
| 100BASE-FX | 光纤链路 | 2000 m |

上述是课件列举的规格；距离还要结合双工模式、光纤类型和具体标准条件理解。

### 3.5.2 吉比特以太网（PDF 98–100页）

1 Gbit/s，兼容以太网帧格式，可有半双工或全双工；半双工用CSMA/CD，全双工不用。

| 标准 | 媒体 | 课件距离 |
|---|---|---:|
| 1000BASE-SX | 多模光纤 | 550 m |
| 1000BASE-LX | 单模/多模光纤，长距对应单模 | 5000 m |
| 1000BASE-CX | 两对屏蔽铜缆 | 25 m |
| 1000BASE-T | 四对5类UTP | 100 m |

半双工为了兼顾64字节最小帧和约100 m网段：

- **载波延伸**：短帧后附特殊符号，使发送占用延伸到512字节时间（4096 bit时间）。MAC帧最小长度本身仍为64字节；延伸符号不是应用数据。
- **分组突发**：第一短帧延伸后，可连续发送若干短帧，只保留必要帧间隔；课件示意突发计时器以1500字节为基准，可略超出。
- 全双工不需要上述两种机制。

### 3.5.3 10吉比特以太网和更快的以太网（PDF 101–102页）

10GE沿用以太网MAC帧结构和最小、最大帧长；**只采用全双工**，不使用CSMA/CD。课件先用早期光纤方案讲解，后表格也列出了铜缆方案，不能记成“10GE只能用光纤”。

| 标准 | 媒体 | 课件距离 |
|---|---|---:|
| 10GBASE-SR | 多模光纤 | 300 m |
| 10GBASE-LR | 单模光纤 | 10 km |
| 10GBASE-ER | 单模光纤 | 40 km |
| 10GBASE-CX4 | 四对双芯铜缆 | 15 m |
| 10GBASE-T | 四对6A类UTP | 100 m |

40GE/100GE表格进一步列出：背板KR、铜缆CR、多模SR、单模LR/ER等，分别覆盖约1 m、7 m、100 m、10 km、40 km等级；示例包括40GBASE-KR4、CR4、SR4、LR4及100GBASE-CR10、SR10/SR4、LR4、ER4。它们是课件中的代表规格，不是所有光模块的统一距离。

以太网从局域网扩展到城域网、广域网：技术成熟、互操作好、成本低，统一帧格式简化管理。

### 3.5.4 使用以太网进行宽带接入（PDF 103页）

优势：双向宽带、按需求升级、端到端以太网无需反复转换帧格式；以太网本身不承担PPP式用户鉴别。

**PPPoE = PPP over Ethernet**：把PPP帧封装在以太网中，结合以太网接入与PPP的链路管理、鉴别能力。课件以ADSL和FTTx用户名密码接入举例。

> 适用范围说明：课件“FTTx都要用PPPoE”的表述过于绝对；这里保留PPPoE接入机制，不把它理解为所有光纤接入的唯一方式。

## 考前速记与自测

| 必会问题 | 答案线索 |
|---|---|
| 为什么先听后发仍会冲突？ | 传播时延，远端尚未听见信号 |
| 最短帧怎么算？ | `L_min≥2τC`，先统一bit、秒单位 |
| 为什么数据至少46字节？ | 最短帧64减首尾18 |
| PPP与以太网是否保证可靠传输？ | 都不靠帧确认、序号提供可靠交付 |
| 交换机依据什么学习、什么转发？ | 源MAC学习，目的MAC转发 |
| 交换机是否隔离广播？ | 默认不隔离，VLAN划分广播域 |
| STP与VLAN的任务相同吗？ | STP防环；VLAN分逻辑广播域 |
| 全双工是否使用CSMA/CD？ | 不使用 |

练习计算：若共享信道速率100 Mbit/s，最大单程传播时延2 μs，则理论最短长度为`2×2 μs×100 Mbit/s=400 bit=50字节`。这是公式练习；若使用标准以太网MAC格式，仍须遵守64字节最小帧长。
