## 4.1 网络层的几个重要概念

### 4.1.1 网络层提供的两种服务（PDF 3–6页）

网络层为不同网络上的主机提供通信。核心争论是：**可靠交付主要由网络负责，还是由端系统负责？**

| 比较 | 虚电路服务 | 数据报服务 |
|---|---|---|
| 设计思路 | 课件设想由网络保障可靠通信 | 可靠交付由端系统按需要实现 |
| 建立连接 | 通信前建立虚电路 | 无需建立网络层连接 |
| 分组地址 | 建立阶段用完整地址，之后可用短虚电路号 | 每个数据报含完整目的地址 |
| 传输路径 | 同一虚电路沿同一路径 | 各数据报独立转发，路径可能不同 |
| 结点故障 | 经过故障点的虚电路受影响 | 可能丢包，路由可改变 |
| 顺序 | 课件模型中保持顺序 | 可能失序、重复、丢失 |
| 差错、流量控制 | 可由网络或主机承担 | 由端系统承担相应职责 |

虚电路是存储转发网络中的**逻辑连接**，不是建立专属物理电路。互联网IP采用**无连接、尽最大努力的数据报服务**，不承诺可靠性、带宽、时限或按序到达。需要可靠通信的应用可以使用TCP等端系统机制；并不是所有运输层协议都可靠。

这样可降低网络内部设备复杂度和成本，使网络适应多样应用。

### 4.1.2 网络层的两个层面（PDF 6–7页）

| 层面 | 主要任务 | 特点 |
|---|---|---|
| 数据层面 / 转发层面 | 查本机转发表，从相应接口转发收到的数据分组 | 本地执行，常由硬件加速 |
| 控制层面 | 路由协议交换信息、算法计算路由、形成转发表 | 服务于转发决策 |

**路由选择**回答“如何得到路由”；**转发**回答“当前分组从哪里出去”。

## 4.2 网际协议 IP

IPv4是本节主要对象。课件同时列出配套的ARP、ICMP、IGMP。ARP报文直接封装在链路层帧中；ICMP、IGMP报文由IP承载。图中协议位置用于说明协作关系，不代表ARP先封装成IP数据报。

### 4.2.1 虚拟互连网络（PDF 9–13页）

异构网络在寻址、最大分组长度、媒体接入、超时、差错恢复、路由和管理等方面不同。互联网没有要求把所有底层网络改成相同技术，而是用路由器和统一的IP层屏蔽这些差异。

| 中间设备 | 主要工作层 | 作用 |
|---|---|---|
| 转发器、集线器 | 物理层 | 扩展信号覆盖 |
| 网桥、二层交换机 | 数据链路层 | 转发MAC帧、扩展局域网 |
| 路由器 | 网络层 | 互连不同IP网络，转发数据报 |

IP网是一个**虚拟互连网络**：用户可用统一IP地址通信，看不见具体链路的异构细节。数据报经路由器逐跳存储转发；最后一跳到目的主机是直接交付，跨网络先交给路由器是间接交付。

### 4.2.2 IP 地址（PDF 13–34页）

#### 一、地址及表示

IPv4地址32位，分成4个8位组，采用点分十进制。如`10000000 00001011 00000011 00011111 = 128.11.3.31`。

地址标识**接口**，不是永久标识一整台机器。主机或路由器连接多个网络时有相应接口地址。公开可路由地址应保持全局唯一；后述私有地址允许在独立网络重复使用。

#### 二、分类编址（历史模型）

`IP地址 = 网络号 + 主机号`。

| 类别 | 固定开头 | 第一字节范围 | 网络号/主机号 | 用途 |
|---|---|---|---|---|
| A | 0 | 0–127；普通A类网络主要为1–126 | 8/24位 | 单播，默认/8 |
| B | 10 | 128–191 | 16/16位 | 单播，默认/16 |
| C | 110 | 192–223 | 24/8位 | 单播，默认/24 |
| D | 1110 | 224–239 | 不按上述两级主机结构解释 | 多播 |
| E | 1111 | 240–255 | 保留类 | 不能当作普通单播池；全1地址另有广播意义 |

课件旧式指派表列：A类126个网络、每网`2^24−2`台主机；B类`2^14−1`个网络、每网`2^16−2`台；C类`2^21−1`个网络、每网254台，并将B首个网络写作128.1、C写作192.0.1。这是**课件沿用的历史分配口径**，不用于判断今天地址是否可分配；当前应以CIDR前缀和特殊用途登记为准。

普通广播子网中：主机位全0为网络地址，全1为定向广播地址。例如历史A类模型的5.6.7.8属于5.0.0.0/8，对应广播5.255.255.255。

| 特殊地址 | 课件含义 | 注意 |
|---|---|---|
| 0.0.0.0 | 本网络本主机、尚未确定地址时使用 | 不是普通主机目的地址 |
| 网络号0、主机号X | 本网络上主机X的历史表示 | 不作为现代一般配置方法 |
| 255.255.255.255 | 本地受限广播 | 路由器不转发 |
| 网络Y、主机位全1 | 对网络Y的定向广播 | 实际是否允许转发受路由器策略约束 |
| 127.0.0.0/8 | 本地环回测试 | 常见127.0.0.1 |

分类编址的优点是管理和转发简单；问题是地址块大小固定、浪费严重，即使划子网也不能根治地址耗尽。

#### 三、无分类编址 CIDR

CIDR（Classless Inter-Domain Routing，无分类域间路由选择）采用：

`IP地址 = 网络前缀（n位） + 主机号（32−n位）`，写成`a.b.c.d/n`。

前缀不再固定为A/B/C类别，n可以取0…32。地址块含`2^(32−n)`个地址；普通广播子网的可用主机地址通常为`2^(32−n)−2`，但/31点对点和/32不能机械减2。

**地址掩码 / 子网掩码**为32位，前n位为1，其余为0：

`网络地址 = IP地址 AND 地址掩码`。

课件核心例：`128.14.35.7/20`。

```text
掩码：255.255.240.0（第三字节11110000）
第三字节：35 AND 240 = 32
网络地址：128.14.32.0/20
地址范围：128.14.32.0 ～ 128.14.47.255
地址总数：2^12 = 4096
普通可分配主机：4094
```

> 课件勘误：PDF 27页图中将/20掩码写成255.255.224.0，该值实际是/19；应以255.255.240.0为准，与25页及27页表格一致。

|---|---|---:|
| /13 | 255.248.0.0 | 524288 |
| /14 | 255.252.0.0 | 262144 |
| /15 | 255.254.0.0 | 131072 |
| /16 | 255.255.0.0 | 65536 |
| /17 | 255.255.128.0 | 32768 |
| /18 | 255.255.192.0 | 16384 |
| /19 | 255.255.224.0 | 8192 |
| /20 | 255.255.240.0 | 4096 |
| /21 | 255.255.248.0 | 2048 |
| /22 | 255.255.252.0 | 1024 |
| /23 | 255.255.254.0 | 512 |
| /24 | 255.255.255.0 | 256 |
| /25 | 255.255.255.128 | 128 |
| /26 | 255.255.255.192 | 64 |
| /27 | 255.255.255.224 | 32 |
| /31 | 255.255.255.254 | 2，适用于点对点链路，两地址均可用 |

IP地址不带前缀长度时，不能在CIDR环境中仅凭外观断定网络地址。课件简写`128.14.32/20`时省略末尾0；实际配置宜写完整四段，避免工具解释差异。

#### 四、路由聚合 / 构造超网

把连续、正确对齐且有共同前缀的地址块汇总为较短前缀，可减少转发表条目。课件将`192.24.0.0/24`至`192.24.15.0/24`汇成`192.24.0.0/20`，16条路由变1条。

分配例：

| 单位 | 地址块 | 地址数 |
|---|---|---:|
| ISP | 206.0.64.0/18 | 16384 |
| 大学 | 206.0.68.0/22 | 1024 |
| 一系 | 206.0.68.0/23 | 512 |
| 二系 | 206.0.70.0/24 | 256 |
| 三系 | 206.0.71.0/25 | 128 |
| 四系 | 206.0.71.128/25 | 128 |

大学需约800个地址，可分/22。对外只通告大学汇总前缀，内部再细分。前缀越短、地址块越大；聚合不能随意把不连续网段拼接，也要确保转发方向适合汇总。

IP编址分等级有利管理与聚合；不同规模网络在IP层平等。课件模型中，普通二层互连的同一IP网络使用共同前缀，不同IP网络由路由器连接；点对点路由器链路可用/31，也可采用未编号接口方案。

### 4.2.3 IP 地址与 MAC 地址（PDF 34–38页）

| 比较 | IP地址 | MAC地址 |
|---|---|---|
| 所属层 | 网络层 | 数据链路层 |
| 出现位置 | IP首部 | 链路层帧首部 |
| 作用范围 | 端到端的逻辑寻址 | 本链路接口间交付 |
| 普通路由转发中 | 源IP、目的IP通常保持 | 每经路由器重新封装，MAC按当前链路变化 |

课件路径`H1 → R1 → R2 → H2`：

| 区间 | IP源→目的 | MAC源→目的 |
|---|---|---|
| H1到R1 | IP1→IP2 | MAC1→MAC3 |
| R1到R2 | IP1→IP2 | MAC4→MAC5 |
| R2到H2 | IP1→IP2 | MAC6→MAC2 |

不要把“IP源、目的不变”误记成整个IP首部不变：TTL和首部检验和会变化；NAT还会修改地址。笔记本移动到其他网络时，通常需要新的IP配置；网卡的MAC身份与地理位置没有直接绑定。

### 4.2.4 地址解析协议 ARP（PDF 38–47页）

ARP解决：**已知本链路下一跳的IPv4地址，求其MAC地址**。不是查询全球任意远端主机MAC的协议。

1. 查ARP高速缓存：存IP、MAC、老化时间、类型等映射。
2. 命中则封装帧发送。
3. 未命中则在本局域网广播ARP请求，包含发送者IP/MAC和目标IP，未知目标硬件地址通常填0。
4. 目标返回ARP响应，通常为单播；双方更新所需缓存映射。
5. 缓存会老化，减少广播并适应设备变化。路由器不转发普通ARP广播请求。

| 发送场景 | 应解析的MAC |
|---|---|
| 主机发往本网络主机 | 目的主机 |
| 主机发往其他网络 | 本网络下一跳路由器 |
| 路由器转发到最终目的网络 | 目的主机 |
| 路由器还须跨网络转发 | 本链路下一跳路由器 |

例如A=209.0.0.5要发给远端B=219.1.0.6，A解析本地网关209.0.0.1的MAC，IP目的仍是B；路由器在B所在链路再解析B的MAC。整个解析过程由协议栈自动完成。

### 4.2.5 IP 数据报的格式（PDF 47–57页）

IPv4数据报由首部与数据组成，固定首部20字节，带选项时首部最多60字节。

| 字段 | 位数 | 含义与单位 |
|---|---:|---|
| 版本 | 4 | IPv4取4 |
| 首部长度IHL | 4 | 单位4字节；5代表20字节，15代表60字节 |
| 区分服务 | 8 | 用于区分服务等处理 |
| 总长度 | 16 | 首部加数据的字节数，最大65535 |
| 标识 | 16 | 同一原始数据报的分片使用相同标识 |
| 标志 | 3 | 保留位、DF、MF；DF=1禁止分片，MF=1表示后面还有片 |
| 片偏移 | 13 | 相对原始数据部分起点，以8字节为单位 |
| TTL | 8 | 生存时间，现代转发按跳递减，减至0丢弃 |
| 协议 | 8 | 指明交付哪个上层协议 |
| 首部检验和 | 16 | 仅检验首部，不检验数据，不是CRC |
| 源地址、目的地址 | 各32 | IP接口地址 |
| 选项及填充 | 可变 | 用于排错、测量等；填充使首部按4字节对齐 |

常见协议值：ICMP=1，IGMP=2，IPv4封装=4，TCP=6，UDP=17，IPv6封装=41，ESP=50，AH=51，ICMPv6=58，OSPF=89。协议号与TCP/UDP端口号不是同一概念。

课件简化写“总长度不超过MTU”，应理解为**在某条链路上传输的每个IP分组/分片**需满足该链路MTU；原始数据报可以大于MTU，需要在允许条件下分片。

#### 分片例4-1

原始总长3820字节，其中首部20、数据3800；每片总长不得超过1420。每片最大数据为`1420−20=1400`，且非末片的数据长度需是8的倍数。

| 分组 | 原数据字节范围 | 数据长度 | 总长 | 标识 | DF | MF | 片偏移 |
|---|---|---:|---:|---:|---:|---:|---:|
| 原始 | 0–3799 | 3800 | 3820 | 12345 | 0 | 0 | 0 |
| 片1 | 0–1399 | 1400 | 1420 | 12345 | 0 | 1 | 0 |
| 片2 | 1400–2799 | 1400 | 1420 | 12345 | 0 | 1 | 175 |
| 片3 | 2800–3799 | 1000 | 1020 | 12345 | 0 | 0 | 350 |

计算：`1400/8=175`，`2800/8=350`。每片都要有首部，不能把数据长度当作总长度。末片MF=0；一个未分片的数据报也可MF=0，所以不能只看MF判断是否曾分片。

TTL每过路由器减1；初始TTL=1的分组不能被第一个路由器继续转发。TTL改变使首部检验和需更新。

首部检验和：先把该字段置0，按16位字进行反码算术求和（最高位进位回卷到最低位），再取反；接收端含检验和求和再取反，正确时为0。选项提供灵活性但增加路由器处理开销，因此课件强调实际较少使用。

## 4.3 IP 层转发分组的过程

### 4.3.1 基于终点的转发（PDF 58–62页）

路由器依据**目的IP**查转发表，逐跳交付，不为每个分组写入完整路径。典型条目是`目的网络前缀 → 下一跳/输出接口`，按网络而非每台主机建表可大幅减小规模。

课件例：H1=128.1.2.194/26，网络为128.1.2.192/26；目标H2=128.1.2.132。`132 AND 192 = 128`，目标属于128.1.2.128/26，与H1不在同一子网，先交网关R1。R1有该子网直连路由，从接口1直接交付H2。

### 4.3.2 最长前缀匹配（PDF 62–69页）

一个目的地址可同时匹配多条路由，选择**匹配前缀最长**的一条，因为它描述的范围最具体。

| 目的128.1.2.196匹配的前缀 | 前缀长度 | 课件动作 |
|---|---:|---|
| 128.1.2.0/24 | 24 | 经R2、接口1 |
| 128.1.2.128/25 | 25 | 直接、接口1 |
| 128.1.2.192/26 | 26 | **选择此条：直接、接口0** |

特殊路由：**主机路由a.b.c.d/32**最具体；**默认路由0.0.0.0/0**在无更具体匹配时使用。

简化流程：取目的D → /32及其他匹配中取最长 → 若仅有默认路由则走默认 → 完全无路由则丢弃，按条件报告差错。直连目的解析主机MAC；非直连解析下一跳MAC。**下一跳IP不替换IP首部的目的地址**，它用于本次链路封装。

## 4.4 网际控制报文协议 ICMP

### 4.4.1 ICMP 报文的种类（PDF 70–72页）

ICMP用于报告网络差错和异常状态，属于网络层，由IP封装（IPv4协议号1）。统一开头为：类型8位、代码8位、检验和16位，其后字段随报文类型变化。

| 大类 | 类型值 | 用途 |
|---|---|---|
| 差错报告 | 3 | 终点不可达 |
| 差错报告 | 11 | 时间超过，例如TTL耗尽 |
| 差错报告 | 12 | 参数问题 |
| 差错报告 | 5 | 改变路由/重定向 |
| 询问 | 8 / 0 | 回送请求 / 回送回答 |
| 询问 | 13 / 14 | 时间戳请求 / 回答 |

差错报告通常带有原数据报首部和原数据的前8字节，帮助源端定位引发差错的通信。ICMP负责报告，并不自动把IP变成可靠服务。

> 课件勘误：72页把ICMP时间戳解释为“自1900年以来的秒数”，与NTP式时间概念混淆。按[RFC 792](https://www.rfc-editor.org/rfc/rfc792.html)，ICMP时间戳是自UTC午夜以来的毫秒数，32位；无法按此格式提供时有非标准值标志。

### 4.4.2 ICMP 的应用举例（PDF 73–76页）

**PING**测试连通性，使用回送请求/回答。它是应用程序直接使用ICMP的例子，不经TCP/UDP。没有回答也可能是过滤或限速，不能单凭一次失败断言主机不存在。

**Traceroute**逐步提高TTL：TTL=1时第一跳丢弃并返回时间超过；TTL=2时第二跳报告；依次获得中间路由器信息。课件描述的经典UDP探测在到达目的后由ICMP端口不可达结束。

> 实现区别补充：Windows命令名为`tracert`，通常使用ICMP回送请求；Unix经典`traceroute`常用UDP，也可选其他探测方式。共同点是递增TTL与ICMP反馈，不应把UDP终点行为套到所有实现。

示例命令（仅供学习，课件以新浪邮件服务器演示；此处未执行外部探测）：

```text
ping mail.sina.com.cn
tracert mail.sina.com.cn
```

## 4.5 IPv6（正文在PDF 117–122页）

课件用IPv4地址资源耗尽说明扩大地址空间的必要性。这里的“耗尽”指相应分配池状态，不是IPv4已停止工作，也不意味着没有存量地址转让或回收。

### 4.5.1 IPv6 的基本首部

IPv6仍提供无连接传送，地址从32位增至128位；支持更丰富的地址层次、扩展首部、自动配置和流相关处理。

`IPv6分组 = 固定40字节基本首部 + 有效载荷`，有效载荷包含零个或多个扩展首部，再接上层数据。

| 字段 | 位数 | 作用 |
|---|---:|---|
| 版本 | 4 | 值为6 |
| 通信量类 | 8 | 区分通信量处理 |
| 流标号 | 20 | 标识相应流 |
| 有效载荷长度 | 16 | 不含40字节基本首部 |
| 下一个首部 | 8 | 后续扩展首部或上层协议 |
| 跳数限制 | 8 | 类似IPv4按跳控制生存范围 |
| 源地址、目的地址 | 各128 | IPv6接口寻址 |

课件示意普通有效载荷上限65535字节；基本首部不含IPv4式首部检验和。扩展首部使选项处理更灵活，课件强调相应8字节对齐要求。

> 表述范围：自动配置并非“IPv6禁止或永远不需要DHCP”；可以使用无状态自动配置，也存在DHCPv6。流标号等支持相关服务机制，不等于IPv6自动保证带宽、时延。

### 4.5.2 IPv6 的地址

课件讲三种基本类型：

| 类型 | 交付对象 |
|---|---|
| 单播unicast | 一个指定接口 |
| 多播multicast | 一组成员 |
| 任播anycast | 一组候选中的一个，通常按路由度量选择最近者 |

本PDF没有详细展开IPv6文本地址压缩规则，不将其混入课件主体。

### 4.5.3 从 IPv4 向 IPv6 过渡

- **双协议栈**：主机或路由器同时实现IPv4、IPv6，按对端和网络条件选择协议。
- **隧道技术**：IPv6分组整体作为IPv4载荷跨越IPv4网络，到出口解封装。课件图中内部源A、目的F仍属于IPv6，外部IPv4头使用隧道入口B和出口E的地址。

IPv6不是能被IPv4设备直接理解的相同报文格式；课件“向后兼容”应理解为通过双栈、隧道等实现渐进共存，不能认为纯IPv6节点天生能直接转发IPv4。

## 4.6 互联网的路由选择协议

### 4.6.1 有关路由选择协议的几个基本概念（PDF 77–80页）

理想算法应正确完整、计算简单、稳定、公平、自适应，并按目标得到合理“最佳”路径。不存在脱离度量和约束的绝对最佳路由。

| 策略 | 优点 | 局限 |
|---|---|---|
| 静态/非自适应 | 简单、开销小 | 不及时适应故障与负载变化 |
| 动态/自适应 | 根据状态更新路由 | 实现复杂，交换与计算有开销 |

互联网规模大且各机构不愿暴露所有内部细节，因此划分**自治系统AS**。一个AS具有统一管理及对外一致的路由策略。

- **IGP内部网关协议**：AS内，域内路由，如RIP、OSPF。
- **EGP外部网关协议**：AS间，域间路由，课件重点为BGP-4。这里EGP是类别名称，不能将它与特定历史EGP协议混同。

### 4.6.2 内部网关协议 RIP（PDF 81–93页）

RIP为分布式**距离向量**协议。各路由器维护到目的网络的距离和下一跳。课件计数：直连网络距离1，每经过一个路由器加1；最大有限度量15，**16表示不可达**。

三个特点：只与相邻路由器交换；交换自己所知的完整路由表；周期交换（课件例30秒），变化时及时通告。

#### 距离向量更新算法

收到邻居X的表后，先把每项距离加1（不超过不可达值16），下一跳改为X，然后逐项处理：

1. 本地没有目的网络：增加该路由。
2. 本地已有且当前下一跳就是X：用新值替换，**即使距离变大也要更新**。
3. 下一跳不是X，但新距离更小：替换。
4. 其他情况保持。
5. 课件例3分钟无邻居更新则将相应路由记为不可达。

基础是Bellman-Ford距离向量思想。所有路由器收敛后可得到正确路径信息，但因为起点不同，**各自路由表并不相同**。

课件87页例：R6旧表Net2=(3,R4)，Net3=(4,R5)；R4通告Net1=3、Net2=4、Net3=1。加1后为4、5、2，下一跳均R4。R6更新为Net1=(4,R4)、Net2=(5,R4)、Net3=(2,R4)。Net2变差仍更新，因为旧下一跳就是R4。

课件88页的完整更新示例：

| 网络 | 旧距离/下一跳 | C通告距离 | 经C距离 | 处理结果 |
|---|---|---:|---:|---|
| Net1 | 7/A | 未通告 | — | 保持7/A |
| Net2 | 2/C | 4 | 5 | 同一下一跳，更新5/C |
| Net3 | 无 | 8 | 9 | 新增9/C |
| Net6 | 8/F | 4 | 5 | 更短，改5/C |
| Net8 | 4/E | 3 | 4 | 同距，按课件规则保持4/E |
| Net9 | 4/F | 5 | 6 | 更差，保持4/F |

RIPv2通过UDP端口520传送，支持CIDR、简单鉴别及多播。基本首部4字节，每条路由20字节，课件不带额外鉴别条目的基本格式最多25项，长`4+20×25=504字节`；字段含地址族、路由标记、网络地址、子网掩码、下一跳、距离。

#### 坏消息传播得慢

当网1故障，R1已知不可达，R2却仍通告旧路径。R1误以为可经R2到达，把距离改3；R2又改4，如此逐步数到16，才一致认为不可达。这就是**计数到无穷**和慢收敛问题。

RIP优点为简单；不足是网络规模小、周期全表交换、故障消息收敛慢。这里“开销小”指实现简单，不等于全表通信量总是很小。

### 4.6.3 内部网关协议 OSPF（PDF 94–100页）

OSPF（开放最短路径优先）是分布式**链路状态**协议，使用Dijkstra/SPF计算路径。它交换“我与哪些邻居相连、链路度量是什么”，不直接周期交换完整路径表。

三个要点：采用洪泛法传播；传播本路由器相邻链路状态；变化时及时更新并周期刷新（课件例30分钟）。同步后的相关区域链路状态数据库LSDB反映拓扑，各路由器以自己为根计算不同路由表。

区域划分降低交换量和维护状态，使协议适于较大AS；代价是层次和报文管理更复杂。

| 名称 | 含义 |
|---|---|
| 主干区域 | Area 0，标识0.0.0.0，连通其他区域 |
| ABR | 区域边界路由器 |
| BR | 主干路由器 |
| ASBR | 自治系统边界路由器 |

> 范围补充：课件先用单区域全网同步解释LSDB，再讲多区域。多区域时不能把“全网数据库一致”理解成所有区域的全部内部拓扑都完全相同；同步有其区域和通告范围。

OSPF五种分组：Hello、数据库描述、链路状态请求、链路状态更新、链路状态确认。直接封装在IP中，**协议号89**，不经TCP/UDP；课件OSPFv2首部24字节。

工作过程：Hello确认邻居 → 交换数据库描述、请求缺失项、同步数据库 → 可靠洪泛更新、确认。课件Hello间隔10秒、40秒未收到判不可达，属于所述场景参数，不能认为所有网络类型固定如此。完全邻接表示相应数据库达到同步；物理相邻不等于已完全邻接。

### 4.6.4 外部网关协议 BGP（PDF 101–105页）

BGP在AS间交换可达性与路径信息，采用**路径向量**。不同AS的代价口径和商业管理策略不同，因此目标是选择可达、无环并符合策略的较好路由，不保证全互联网某个统一最短路径。

AS选择BGP发言人。两个对等体先建立TCP连接，再建立BGP会话并交换信息。路径包含到目标网络经过的AS序列，结合策略选择路径；例如课件AS2向AS1通告经AS2可达N1…N4，主干可通告经(AS1,AS3)到达其他网络。

| 比较 | RIP | OSPF | BGP |
|---|---|---|---|
| 范围 | AS内 | AS内 | AS间为本节重点 |
| 算法思想 | 距离向量 | 链路状态/SPF | 路径向量 |
| 主要交换信息 | 路由表与距离 | 相邻链路状态 | 网络可达性、AS路径与策略信息 |
| 传播方式 | 邻居交换 | 区域范围可靠洪泛 | 对等会话交换 |
| 承载 | UDP/520 | 直接IP，协议89 | TCP |
| 主要特点 | 简单、最大有限距离15 | 收敛快、可分区域 | 强调策略和AS间可达性 |

## 4.8 虚拟专用网 VPN 和网络地址转换 NAT

课件先讲私有地址与NAT，再讲VPN；这里保留4.8.1、4.8.2编号，先交代共同的私有地址概念。

### 本地互联网与私有地址（PDF 106–108、112页）

内部网络可自行分配本地地址，但若随意与公网地址重叠，就会产生歧义。RFC 1918规定三段私有地址，允许不同机构复用，不能在公共互联网按普通公网目的地址路由。

| 私有地址块 | 范围 | 主机位数 |
|---|---|---:|
| 10.0.0.0/8 | 10.0.0.0–10.255.255.255 | 24 |
| 172.16.0.0/12 | 172.16.0.0–172.31.255.255 | 20 |
| 192.168.0.0/16 | 192.168.0.0–192.168.255.255 | 16 |

注意不是所有172开头的地址都是私有；课件NAT公网示例172.38.1.5不在172.16/12内。

### 4.8.1 虚拟专用网 VPN（PDF 113–116页）

VPN利用公共互联网承载机构内部通信，在效果上形成专用网，不必为所有网点铺设专线。“虚拟”描述承载方式，“专用”描述访问与通信范围。

有保密要求时，须使用提供相应保护的加密方案；**隧道封装本身不等于加密**。课件示例为加密内部数据报后再加外部IP头：

```text
内层：X 10.1.0.1 → Y 10.2.0.3
入口R1公网：125.1.2.3
出口R2公网：194.4.5.6
外层：125.1.2.3 → 194.4.5.6
载荷：被保护的内部数据报；到R2后解封装并交付Y
```

课件区分：同一机构内部的内联网intranet；与外部合作机构组成的外联网extranet；流动员工经软件建立隧道访问单位网络的远程接入VPN。

### 4.8.2 网络地址转换 NAT（PDF 108–112页）

NAT路由器位于专用网与互联网边界，具有全球地址，按转换表改写IP地址。

| 方向 | 改写字段 | 课件例 |
|---|---|---|
| 出站 | 源IP | 192.168.0.3 → 172.38.1.5 |
| 回站 | 目的IP | 172.38.1.5 → 192.168.0.3 |

课件109页外部主机示意有213.18.2.4与213.28.2.4混写；本笔记按图中主要地址213.18.2.4理解。传统一对一动态NAT不靠端口复用，n个公网地址的池在课件模型中同时支持n个内部地址映射，不能让所有内机无限同时共享同一个公网地址。

**NAPT：网络地址与端口号转换**将不同内部会话映射为同一公网IP的不同端口：

| 方向 | 原地址:端口 | 转换后 |
|---|---|---|
| 出 | 192.168.0.3:30000 | 172.38.1.5:40001 |
| 出 | 192.168.0.4:30000 | 172.38.1.5:40002 |
| 入 | 172.38.1.5:40001 | 192.168.0.3:30000 |
| 入 | 172.38.1.5:40002 | 192.168.0.4:30000 |

通常由内网先发起建立动态映射，回包才能找到内部会话。课件“内网不能当服务器”限定于**没有额外静态映射等配置的动态NAT/NAPT模型**；实际端口映射可提供入站服务。NAT负责地址改写，不提供VPN式加密，也不能替代完整防火墙策略。
