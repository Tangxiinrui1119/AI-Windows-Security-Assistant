## 0. 应用层与应用层协议（PDF 2～3页）

### 0.1 应用层的作用

运输层为应用进程提供端到端的通信服务。不同网络应用进程需要不同的通信规则，因此需要不同的应用层协议。

应用层由各种应用层协议组成，每个协议解决一类网络应用问题。课件列举：

| 网络应用 | 应用层协议 |
|---|---|
| 万维网 | HTTP |
| 电子邮件 | SMTP、POP3 |
| 文件传输 | FTP |

### 0.2 应用层协议规定什么？

应用层协议精确定义不同主机中的多个应用进程之间的通信规则，主要包括：

1. **报文类型**：应用进程交换什么类型的报文，例如请求报文、响应报文。
2. **报文语法**：报文有哪些字段，各字段如何组织。
3. **字段语义**：字段中的信息分别表示什么。
4. **交互规则**：进程何时、如何发送报文，以及如何响应。

许多应用采用客户—服务器方式：

- 客户（client）：服务请求方，运行客户应用进程。
- 服务器（server）：服务提供方，运行服务器应用进程。

## 6.1 域名系统 DNS

### 6.1.1 域名系统概述（PDF 4～5页）

DNS（Domain Name System，域名系统）是互联网使用的命名系统，主要作用是**把人们使用的域名转换为相应的IP地址**，为互联网应用提供核心服务。

例如，用户访问学校网站时输入域名，浏览器需要通过DNS查询对应的IP地址，之后才能向目标主机发起通信。

DNS的特点：

- 域名采用层次树状结构。
- DNS是一个联机的分布式数据库系统。
- 采用客户—服务器方式。
- 域名到IP地址的解析由多个域名服务器程序共同完成。
- 域名服务器程序运行在专门的结点上，该机器称为域名服务器。

课件在域名解析示意图中标明DNS使用UDP通信。

### 6.1.2 互联网的域名结构（PDF 6～8页）

#### 一、层次树状命名

域名采用层次树状结构。域（domain）是名字空间中一个可被管理的划分；一个域可以继续划分为子域，子域还可以继续划分，形成顶级域、二级域、三级域等。

例如：**mail.cctv.com**

| 标号 | 含义 |
|---|---|
| mail | 三级域名，级别较低 |
| cctv | 二级域名 |
| com | 顶级域名，级别最高 |

域名由一系列标号（label）组成，各标号之间用点号分隔。

课件给出的域名规则：

- 每个标号不超过63个字符。
- 完整域名总共不超过255个字符。
- 域名不区分英文字母大小写。
- 域名是逻辑概念，不代表计算机所在的物理地点。
- 互联网名字空间按机构组织划分，与物理网络、IP地址中的子网没有直接关系。

#### 二、顶级域名 TLD

课件将全球顶级域名分为几类：

| 类型 | 含义 |
|---|---|
| 国家顶级域名 nTLD | 按国家或地区设置，例如.cn、.uk |
| 通用顶级域名 gTLD | 例如.com、.net、.org、.edu、.gov |
| 基础结构域名 | 课件列举.arpa |
| 新顶级域名 New gTLD | 由ICANN申请、审核的新顶级域名 |

在国家顶级域名下注册的二级域名由各国家自行确定。课件指出，我国把二级域名划分为“类别域名”和“行政区域名”两大类。

### 6.1.3 域名服务器（PDF 8～14页）

DNS使用分布在各地的域名服务器。课件按照作用将其分为四类：

#### 1. 根域名服务器

- 位于域名层次结构的最高层。
- 知道顶级域名服务器的域名和IP地址。
- 当本地域名服务器无法解析某个域名时，会向根域名服务器查询。
- **根域名服务器通常不直接返回最终主机IP地址，而是告诉本地域名服务器下一步应查询哪个顶级域名服务器。**

课件介绍了13套根服务器系统，并强调：

- 13个根服务器名称并不代表全球只有13台物理机器。
- 根服务器分布在世界各地，每个地点可以部署多台机器。
- 根服务器采用任播（anycast）技术，使DNS客户的查询能够到达较近的根服务器。

#### 2. 顶级域名服务器（TLD服务器）

负责管理在该顶级域名下注册的所有二级域名。

收到DNS查询后，可能直接给出相应回答，也可能告诉查询方下一步应找哪个域名服务器。

#### 3. 权限域名服务器

- 负责一个区（zone）的域名服务器。
- 保存其管辖区内主机的域名与IP地址映射。
- 如果自己无法给出最终答案，会告诉查询方下一步应查询哪个权限域名服务器。

**域（domain）与区（zone）不是完全相同的概念。** 课件图示说明，一个区可以等于一个域，也可以小于一个域；具体划分由组织的管理需要决定。

#### 4. 本地域名服务器

- 主机发出DNS查询请求时，通常先把请求发送给本地域名服务器。
- ISP或大学都可以拥有自己的本地域名服务器。
- 如果所查询的主机属于本地服务器能够直接解析的范围，就可以直接返回结果。
- 本地域名服务器有时也称为默认域名服务器。

#### 五、提高域名服务器可靠性

课件介绍主域名服务器与辅助域名服务器：

- DNS数据会复制到多个域名服务器中保存。
- 主域名服务器发生故障时，辅助域名服务器可以继续提供查询服务。
- 主域名服务器定期向辅助域名服务器复制数据。
- 课件所述的数据更改在主域名服务器中进行，以保证数据一致性。

### 6.1.4 域名解析过程（PDF 14～16页）

域名解析就是把域名转换为IP地址的过程。课件重点区分**递归查询**和**迭代查询**。

#### 一、递归查询

通常用于主机向本地域名服务器发出查询请求的场景。

主机提出查询后，希望本地域名服务器最终返回所需结果。如果本地域名服务器不知道答案，就继续代替DNS客户向其他域名服务器查询，最后把结果返回给主机。

理解：**客户把解析任务交给本地域名服务器，由本地域名服务器负责把结果找回来。**

#### 二、迭代查询

通常用于本地域名服务器向根域名服务器查询的场景。

被查询的服务器如果不知道最终答案，就返回下一步应当查询的域名服务器信息。本地域名服务器再向下一台服务器发出查询。

以查询某个域名为例：

1. 主机向本地域名服务器发出查询。
2. 本地域名服务器向根域名服务器查询。
3. 根域名服务器返回对应顶级域名服务器的信息。
4. 本地域名服务器向顶级域名服务器查询。
5. 顶级域名服务器返回下一步应查询的权限域名服务器信息。
6. 本地域名服务器向权限域名服务器查询。
7. 权限域名服务器返回最终的IP地址。
8. 本地域名服务器把结果返回给主机。

#### 三、递归与迭代的区别

| 对比 | 递归查询 | 迭代查询 |
|---|---|---|
| 常见场景 | 主机向本地域名服务器查询 | 本地域名服务器向根、顶级等服务器查询 |
| 查询方期待什么 | 最终结果 | 最终结果或下一步服务器的信息 |
| 谁继续查询 | 被请求的服务器代为继续查询 | 原查询方根据提示继续查询 |

课件指出，递归查询也可以发生在域名服务器之间，但这种方式比较少用。

#### 四、DNS高速缓存

域名服务器广泛使用高速缓存，保存最近查询过的DNS记录。

作用：

- 减轻各级域名服务器的负荷。
- 减少DNS查询请求和回答报文的数量。
- 提高重复查询的效率。

缓存记录需要设置计时器，超时后删除，避免长期使用过期记录。

## 6.2 文件传送协议 FTP

### 6.2.1 FTP概述（PDF 17页）

FTP（File Transfer Protocol，文件传送协议）用于在网络中传送文件。

课件强调的特点：

- 提供交互式访问，允许客户指定文件类型和格式。
- 可以设置文件存取权限。
- 屏蔽不同计算机系统的细节，适合异构网络之间传送文件。
- 是文件共享协议中的一类。

网络环境下复制文件可能遇到的问题：

1. 不同计算机存储数据的格式不同。
2. 文件目录结构和命名规定不同。
3. 操作系统对文件操作使用的命令不同。
4. 访问控制方法不同。

FTP提供基本文件传送服务，减少或消除不同操作系统处理文件时的不兼容性。

### 6.2.2 FTP的基本工作原理（PDF 18～19页）

FTP使用TCP提供可靠的运输服务，采用客户—服务器方式。

一个FTP服务器进程可以同时为多个客户进程提供服务。服务器进程由两部分组成：

- **主进程**：负责接受新的请求。
- **从属进程**：负责处理单个客户请求。

FTP主进程的工作步骤：

1. 打开熟知端口21，使客户进程能够连接。
2. 等待客户进程发出连接请求。
3. 启动从属进程处理客户请求；请求处理完毕后，从属进程终止。
4. 主进程返回等待状态，继续接受其他客户请求。主进程和从属进程可以并发处理。

#### ⭐ FTP为什么使用两个TCP连接？

FTP在客户与服务器之间建立两个不同用途的TCP连接：

| 连接 | 作用 | 生命周期 | 课件端口 |
|---|---|---|---:|
| 控制连接 | 传输客户发出的命令和传送请求 | 整个FTP会话期间保持打开 | 服务器端口21 |
| 数据连接 | 实际传送文件 | 传输文件时动态创建，传送完毕后释放 | 课件图示服务器端口20 |

工作过程可以理解为：

1. 客户先建立控制连接，向服务器发送文件传送请求。
2. 服务器控制进程收到请求后，创建数据传送进程并建立数据连接。
3. 数据连接负责实际文件传送。
4. 文件传送结束后，数据连接关闭；控制连接仍可继续使用。

**易混淆：控制连接负责“谈事情、发命令”，数据连接负责“真正传文件”。**

## 6.3 远程终端协议 TELNET

### 6.3.1 TELNET概述（PDF 20～21页）

TELNET（远程终端协议）是一个简单的远程终端协议，也称为**终端仿真协议**。

它允许用户在本地通过TCP连接登录到远程主机：

- 用户在本地系统运行TELNET客户进程。
- 远地主机运行TELNET服务器进程。
- 用户的键盘输入被传送到远地主机。
- 远地主机的输出通过TCP连接返回到用户屏幕。

TELNET采用客户—服务器方式。服务器主进程等待新的请求，并创建从属进程处理连接。

### 6.3.2 网络虚拟终端 NVT 格式（PDF 21～22页）

不同操作系统对字符和文本行结束的表示可能不同，例如回车、换行或回车加换行。

TELNET使用网络虚拟终端NVT（Network Virtual Terminal）格式，作为客户端与服务器之间统一的数据和命令表示方式。

基本过程：

1. 客户端把用户击键和命令转换成NVT格式，再发送给服务器。
2. 服务器收到NVT数据后，将其转换成远地系统需要的格式。
3. 服务器向客户返回数据时，先把远地系统格式转换成NVT格式。
4. 本地客户端再把NVT格式转换成本地系统所需的格式。

课件把NVT字符分为两类：

- 数据字符：首位为0。
- 控制字符：首位为1。

**理解：NVT相当于双方约定的中间表示格式，用来屏蔽不同操作系统在终端数据表示上的差异。**

## 6.4 万维网 WWW

### 6.4.1 万维网概述（PDF 23～25页）

WWW（World Wide Web，万维网）**并不是某种特殊的计算机网络**，而是一个大规模的、联机式的信息储藏所。

它通过链接，使用户能够从互联网上一个站点访问另一个站点，按需获取信息。

#### 一、超文本与超媒体

万维网是分布式超媒体系统，是超文本系统的扩充。

| 概念 | 含义 |
|---|---|
| 超文本（hypertext） | 由多个文本信息源通过链接组织起来 |
| 超媒体（hypermedia） | 在文本之外，还可以包含图形、图像、声音、动画和视频等内容 |

万维网是分布式系统：

- 信息分布在整个互联网中。
- 每台主机上的文档独立管理。
- 各主机对文档的操作不需要相互通知。

#### 二、万维网的工作方式

WWW采用客户—服务器方式：

- 客户程序：浏览器。
- 服务器程序：运行在存放万维网文档的计算机上，也称万维网服务器。
- 浏览器向服务器发送请求。
- 服务器返回浏览器所需要的文档。
- 显示在客户程序主窗口中的万维网文档称为页面（page）。

#### 三、万维网必须解决的四个问题

| 问题 | 解决办法 |
|---|---|
| 如何标识互联网上的文档 | 使用URL统一资源定位符 |
| 如何实现万维网上的链接 | 使用HTTP超文本传送协议 |
| 如何让不同作者制作的文档能在不同主机上显示 | 使用HTML超文本标记语言 |
| 如何帮助用户找到所需信息 | 使用搜索工具，即搜索引擎 |

### 6.4.2 统一资源定位符 URL（PDF 26～29页）

URL（Uniform Resource Locator，统一资源定位符）用于简洁表示互联网上资源的位置和访问方法，可以理解为网络范围内的资源地址。

资源包括文件目录、文件、文档、图像、声音，以及其他可以通过互联网访问的数据。

#### 一、URL的一般格式

**协议://主机:端口/路径**

| 部分 | 含义 |
|---|---|
| 协议 | 规定访问资源所使用的方法，例如FTP、HTTP |
| 主机 | 存放资源的主机域名，也可以是IP地址 |
| 端口 | 服务器提供服务的端口；省略时使用默认端口 |
| 路径 | 资源所在的目录或位置；课件指出路径区分大小写，省略时使用默认路径 |

URL中协议和主机等部分遵循规定格式。课件指出URL字符大小写没有统一要求，但资源路径需要区分大小写。

#### 二、HTTP URL示例

**http://www.bistu.edu.cn/publish/newthu/newthu_cnt/faculties/index.html**

- 协议：HTTP。
- 主机：www.bistu.edu.cn。
- 端口：省略时使用HTTP默认端口80。
- 路径：/publish/newthu/newthu_cnt/faculties/index.html。

如果路径省略，课件说明通常指向该网站的某个主页。

### 6.4.3 超文本传送协议 HTTP（PDF 29～42页）

HTTP（HyperText Transfer Protocol，超文本传送协议）是面向事务的应用层协议，用于规定浏览器和万维网服务器之间通信的格式与规则。

课件强调：

- HTTP使用TCP连接进行可靠传送。
- 可以传输文本、超文本、声音、图像等多媒体信息。
- HTTP请求和响应由ASCII码串构成。
- HTTP本身是无状态的，课件也将其描述为无连接协议。

**注意：HTTP使用TCP进行可靠传输，不等于HTTP应用协议本身就具有连接状态。** 课件中的“无连接、无状态”是HTTP协议自身的特征；TCP连接的建立与释放属于运输层。

#### 一、HTTP的基本操作过程

1. 浏览器根据URL确定目标服务器。
2. 浏览器与服务器建立TCP连接。
3. 浏览器发送HTTP请求报文。
4. 服务器返回HTTP响应报文。
5. 根据所采用的连接方式，继续使用或释放TCP连接。

课件以HTTP默认端口80作为服务器监听端口的示例。

用户访问页面的两种方式：

- 在浏览器地址栏输入URL。
- 在已有页面中点击超链接，由浏览器访问链接指向的页面。

#### 二、HTTP的主要特点

- 使用TCP作为运输层协议，保证数据可靠传输。
- HTTP协议本身是无状态的。
- 课件将HTTP描述为无连接协议。
- 无状态简化了服务器设计，使服务器更容易支持大量并发请求。

#### 三、非持续连接与持续连接

**1. HTTP/1.0：非持续连接**

课件指出，HTTP/1.0每请求一个文档，就要重新建立TCP连接。

请求一个文档的时间至少包括：

- 1个RTT：TCP三次握手建立连接。
- 1个RTT：发送HTTP请求并接收响应开始。
- 文档传输时间。

因此课件给出的估算为：

**所需时间 ≥ 2 RTT + 文档传输时间**

如果主页包含10个图片链接，每个对象都需要重新建立连接，就会产生大量RTT开销；课件示例估算为至少22 RTT，再加上各文档传输时间。

缺点：

- 每请求一个文档都需要新的TCP连接。
- 每次建立连接都需要分配缓存和变量。
- 连接反复建立、释放，增加服务器负担和时延。

**2. HTTP/1.1：持续连接**

持续连接（persistent connection）指服务器发送响应后，在一段时间内不释放TCP连接，使同一个客户可以继续通过这条连接发送后续请求并接收响应。

只要文档都在同一个服务器上，就可以继续使用同一条TCP连接。

持续连接有两种方式：

| 方式 | 工作过程 | 特点 |
|---|---|---|
| 非流水线方式 | 收到前一个响应后，客户才发送下一个请求 | 连接可能处于空闲状态 |
| 流水线方式 | 不必等待前一个响应，就可以连续发送后续请求 | 多个请求连续到达服务器，服务器可连续返回响应，下载效率提高 |

课件图示对比：

- 非流水线方式：连接建立后，多个对象依次请求，期间可能出现空闲等待。
- 流水线方式：请求可以连续发送，减少等待时间。

#### 四、代理服务器与Web高速缓存（PDF 34～37页）

代理服务器（proxy server）也称万维网高速缓存（Web cache），它代表浏览器向源点服务器发出HTTP请求。

作用：如果缓存中已有用户请求的对象，就可以直接返回，减少访问互联网源点服务器的时延，并减轻网络链路负担。

工作过程：

1. 浏览器先与校园网中的高速缓存建立TCP连接，并发送HTTP请求。
2. 如果缓存中已有所请求对象，就把对象放入HTTP响应报文返回浏览器。
3. 如果缓存中没有对象，代理服务器代表浏览器与互联网源点服务器建立TCP连接并发送请求。
4. 源点服务器把对象放入HTTP响应报文，返回给代理服务器。
5. 代理服务器把对象复制到本地存储器留待以后使用，再通过已有连接返回浏览器。

#### 五、HTTP报文结构

HTTP报文分为两类：

- 请求报文：客户发送给服务器。
- 响应报文：服务器发送给客户。

课件将HTTP描述为面向正文的协议，字段值使用ASCII码串，字段长度不固定。

两类报文都由三个部分组成：

1. **开始行**：请求报文中是请求行；响应报文中是状态行。
2. **首部行**：包含浏览器、服务器或报文主体的相关信息，可以有多行。
3. **实体主体**：承载报文主体数据；请求报文中通常不用，响应报文也可能没有。

##### 1. 请求报文

请求行的一般结构：

**方法 + URL + HTTP版本**

之后是若干首部字段，每个字段占一行；首部结束后有一个空行，后面可以有实体主体。

请求方法是对URL所标志资源进行的操作。

| 方法 | 课件给出的含义 |
|---|---|
| OPTION | 请求一些选项的信息 |
| GET | 请求读取URL所标志的信息 |
| HEAD | 请求读取URL所标志信息的首部 |
| POST | 给服务器添加信息，例如注释 |
| PUT | 在指明的URL下存储一个文档 |
| DELETE | 删除URL所标志的资源 |
| TRACE | 用于环回测试 |
| CONNECT | 用于代理服务器 |

请求报文示例的字段含义：

- GET：请求读取某个页面。
- Host：给出目标主机域名。
- Connection: close：告诉服务器发送完请求文档后释放连接。
- User-Agent：表明客户使用的浏览器信息。
- Accept-Language：表明客户希望优先得到的语言版本。
- CRLF：请求报文最后的空行，用于分隔首部和实体主体。

##### 2. 响应报文

响应报文的开始行是状态行，一般结构：

**HTTP版本 + 状态码 + 短语**

之后是首部行、空行和可选的实体主体。

- 版本：HTTP版本。
- 状态码：服务器操作完成的状态。
- 短语：对状态码的文字解释。

##### 3. HTTP状态码

状态码为三位数字，分为五类：

| 状态码范围 | 含义 |
|---|---|
| 1xx | 通知信息，例如请求已收到或正在处理 |
| 2xx | 成功 |
| 3xx | 重定向，需要进一步行动才能完成请求 |
| 4xx | 客户端差错，例如请求语法错误或无法完成 |
| 5xx | 服务器差错，例如服务器失效，无法完成请求 |

课件示例：

- **HTTP/1.1 200 OK**：成功。
- **HTTP/1.1 404 Not Found**：找不到请求的资源。

#### 六、Cookie与状态信息（PDF 42页）

HTTP是无状态的，但实际网站有时需要识别同一个用户在不同请求之间的关联。

课件介绍使用Cookie跟踪HTTP服务器和客户之间传递的状态信息：

1. 用户首次访问网站。
2. 服务器为用户创建唯一识别码。
3. 服务器在HTTP响应中通过Set-Cookie返回识别码。
4. 浏览器保存Cookie。
5. 用户以后再次访问时，浏览器在HTTP请求中发送Cookie。
6. 服务器根据Cookie识别用户并处理请求。

理解：**Cookie让服务器能够把不同请求与某个用户关联起来。**

### 6.4.4 万维网的文档（PDF 43～49页）

## 6.5 电子邮件

### 6.5.1 电子邮件概述（PDF 54～60页）

电子邮件（e-mail）指使用电子设备交换邮件及其方法。

课件列出的优点：

- 使用方便、传递迅速、费用低廉。
- 可以传送文字、声音、图像等多种类型的信息。

电子邮件系统涉及的重要协议和标准：

- SMTP：简单邮件传送协议。
- 互联网文本报文格式。
- MIME：通用互联网邮件扩充。
- POP3和IMAP：邮件读取协议。

#### 一、电子邮件系统的三个主要构件

1. 用户代理（UA）。
2. 邮件服务器。
3. 邮件发送和读取协议。

**用户代理（User Agent）**是用户与电子邮件系统之间的接口，也称电子邮件客户端软件。基本功能包括撰写、显示、处理和通信。

**邮件服务器（Mail Server）**又称邮件传输代理，负责发送和接收邮件，并向发信人报告邮件传送情况。它按照客户—服务器方式工作。

#### 二、邮件发送和读取协议

| 协议 | 作用 |
|---|---|
| SMTP | 用户代理向邮件服务器发送邮件，以及邮件服务器之间传送邮件 |
| POP3 | 用户代理从邮件服务器读取邮件 |
| IMAP | 用户代理访问和管理邮件服务器中的邮件 |

SMTP和POP3（或IMAP）都使用TCP连接可靠传送邮件。

邮件发送和读取可以理解为：

- 发送邮件是“推”（push）：通过SMTP把邮件送到邮件服务器。
- 读取邮件是“拉”（pull）：通过POP3或IMAP从邮件服务器读取邮件。

**不要把SMTP和POP3/IMAP混为一谈：SMTP负责发送，POP3/IMAP负责读取。**

#### 三、电子邮件的信封与内容

电子邮件由两部分组成：

- **信封（envelope）**：邮件传输程序根据其中的信息传送邮件，最重要的是收件人地址。
- **内容（content）**：用户读取邮件时看到的内容。

课件给出的电子邮件地址格式：

**收件人邮箱名@邮箱所在主机的域名**

例如：**xiexiren@bistu.edu.cn**

其中用户名在该域名范围内唯一，邮箱所在主机的域名在全世界范围内唯一。

### 6.5.2 简单邮件传送协议 SMTP（PDF 61～66页）

SMTP（Simple Mail Transfer Protocol）规定两个相互通信的SMTP进程之间如何交换信息。

特点：

- 采用客户—服务器方式。
- 基于TCP通信。
- 使用TCP熟知端口25。
- 是基于文本（ASCII码）的命令—响应协议。

#### 一、SMTP通信的三个阶段

**1. 连接建立**

发送方的SMTP客户与接收方的SMTP服务器建立TCP连接。课件示意图中，接收方SMTP服务器使用熟知端口25。

连接建立后：

- 服务器发送220，表示Service Ready（服务就绪）。
- 客户发送HELO命令，并附上发送方主机名。
- 服务器返回250 OK，表示可以接收邮件。

**2. 邮件传送**

课件示例中的主要命令和响应：

| 命令或响应 | 含义 |
|---|---|
| MAIL FROM | 指定发件方地址 |
| RCPT TO | 指定收件方地址 |
| DATA | 开始传送邮件内容 |
| 354 Start mail input | 服务器允许客户开始输入邮件内容 |
| 单独一行的点号 | 表示邮件内容结束 |
| 250 OK | 服务器确认接受 |

邮件内容示例包括From、To、Date、Subject等首部，以及正文主体。

**3. 连接释放**

邮件发送完成后，客户发送QUIT命令；服务器返回221 Service closed，然后释放TCP连接。

> 课件示意图强调发送主机的SMTP客户与接收主机的SMTP服务器建立连接；中间邮件服务器转发的完整互联网邮件路由细节未在本课件中展开。

### 6.5.3 电子邮件的信息格式（PDF 66～67页）

RFC 5322规定邮件内容中的首部（header）格式，邮件主体（body）由用户自由撰写。

邮件内容的结构：

1. 首部（header）。
2. 空行。
3. 主体（body）。

课件列举的首部字段：

| 字段 | 含义 |
|---|---|
| From | 发件人 |
| To | 收件人 |
| Date | 日期 |
| Subject | 主题 |
| Cc | 抄送 |

课件指出邮件首部是纯文本信息（ASCII编码），并不具有复杂的固定结构。

### 6.5.4 邮件读取协议 POP3 和 IMAP（PDF 67～69页）

两种常见邮件读取协议：

- POP3：邮局协议第3个版本。
- IMAP：网际报文存取协议。

二者都采用客户—服务器方式，基于TCP通信。

课件给出的简化对比：

| 操作 | IMAP | POP3（课件对比口径） |
|---|---|---|
| 阅读、标记、移动、删除收件箱邮件 | 客户端与邮箱更新同步 | 仅在客户端内 |
| 保存已发送邮件 | 客户端与邮箱更新同步 | 仅在客户端内 |
| 创建自定义文件夹 | 客户端与邮箱更新同步 | 仅在客户端内 |
| 保存草稿 | 客户端与邮箱更新同步 | 仅在客户端内 |
| 垃圾邮件文件夹 | 支持 | 课件表格标为不支持 |
| 广告邮件文件夹 | 支持 | 课件表格标为不支持 |

**重点：SMTP用于发送邮件；POP3或IMAP用于从目的邮件服务器读取邮件。** 两者承担的任务不同。

### 6.5.5 基于万维网的电子邮件（PDF 69～70页）

传统用户代理的不足：

- 需要在计算机中安装用户代理软件。
- 收发邮件不够方便。

基于万维网的电子邮件：

- 不需要在计算机中安装专门的用户代理软件。
- 只要计算机能够联网，就可以通过网站收发邮件。
- 界面友好。

协议分工：

- 用户与邮件网站之间发送、读取邮件时使用HTTP。
- 两个邮件服务器之间传送邮件时使用SMTP。
- 课件示例中，使用HTTP POST提交要发送的邮件，使用HTTP GET读取邮件。

> **MIME范围说明：** 课件目录和6.5.1概述列出了MIME，但正文没有展开MIME的格式与编码细节。本笔记不自行补充其工作原理。

## 6.6 动态主机配置协议 DHCP（PDF 71～79页）

### 6.6.1 为什么需要DHCP？

协议软件在使用前必须正确配置。课件指出，连接到互联网的计算机需要配置的参数包括：

1. IP地址。
2. 子网掩码。
3. 默认路由器的IP地址。
4. 域名服务器的IP地址。

在协议软件中给协议参数赋值的动作称为协议配置。

DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）提供即插即用连网（plug-and-play networking）机制，使计算机加入网络时可以自动获取IP地址，而不必手工配置。

课件指出：

- 位置固定、运行服务器软件的计算机可以被指派永久地址。
- 运行客户端软件的计算机可以获得临时地址。

### 6.6.2 DHCP的客户—服务器方式

需要IP地址的主机启动时，向DHCP服务器广播发送发现报文DHCPDISCOVER，此时该主机成为DHCP客户。

DHCP服务器收到发现报文后：

- 先在数据库中查找该计算机的配置信息。
- 如果找到，就返回对应配置信息。
- 如果找不到，就从IP地址池（address pool）中取一个地址分配给该计算机。
- 服务器的回答报文称为DHCPOFFER。

DHCP基于UDP工作：

| 角色 | 端口 |
|---|---:|
| DHCP服务器 | UDP 67 |
| DHCP客户 | UDP 68 |

### 6.6.3 ⭐ DHCP四步工作过程（DORA）

这是本节最重要的工作流程。

| 步骤 | 报文 | 方向与作用 |
|---|---|---|
| 1 | DHCPDISCOVER | 客户广播发现报文，寻找DHCP服务器 |
| 2 | DHCPOFFER | 服务器提供IP地址等配置信息 |
| 3 | DHCPREQUEST | 客户从收到的服务器提供中选择一个，并请求使用该地址 |
| 4 | DHCPACK | 被选择的服务器确认，客户可以开始使用获得的临时IP地址 |

课件图示中的关键细节：

1. 客户最初还没有可用的IP地址，因此DHCPDISCOVER广播到255.255.255.255。
2. DHCP服务器发送DHCPOFFER，提供IP地址、默认网关和子网掩码等信息。
3. 客户可能收到多个DHCP服务器的DHCPOFFER。
4. 客户从中选择一个服务器，发送DHCPREQUEST。
5. 被选择的服务器发送DHCPACK，客户进入已绑定状态。

记忆顺序：

**Discover（发现） → Offer（提供） → Request（请求） → ACK（确认）**

### 6.6.4 租用期与续租（PDF 74～79页）

DHCP服务器分配给客户的IP地址是临时的，客户只能在有限时间内使用，这段时间称为**租用期（lease period）**。

- 租用期由DHCP服务器决定。
- DHCP客户也可以在发送报文时提出租用期要求。

假设租用期为T，课件给出的两个计时器：

- T1 = 0.5T，即租用期经过一半。
- T2 = 0.875T，即租用期经过87.5%。

续租过程：

1. 到达T1时，DHCP客户发送DHCPREQUEST，请求更新租用期。
2. 如果服务器同意，返回DHCPACK，客户得到新的租用期并重新设置计时器。
3. 如果服务器返回DHCPNACK，客户必须立即停止使用原来的IP地址，并重新申请。
4. 如果服务器没有响应T1时的请求，客户在租用期达到T2时必须再次发送DHCPREQUEST。
5. 客户可以提前终止租用期，向服务器发送DHCPRELEASE。

### 6.6.5 DHCP常见报文速查

| 报文 | 含义 |
|---|---|
| DHCPDISCOVER | 客户发现服务器 |
| DHCPOFFER | 服务器提供地址与配置信息 |
| DHCPREQUEST | 客户请求使用或续租地址 |
| DHCPACK | 服务器确认 |
| DHCPNACK | 服务器否认请求 |
| DHCPRELEASE | 客户主动释放租用的地址 |

## 6.7 简单网络管理协议 SNMP

### 6.7.1 网络管理的基本概念（PDF 80～87页）

网络管理是对硬件、软件和人力资源进行综合协调，以监视、测试、配置、分析、评价和控制网络资源，满足网络性能和服务质量等需求。

#### 一、网络管理的五大功能

| 功能 | 作用 |
|---|---|
| 故障管理 | 故障检测、隔离和纠正 |
| 配置管理 | 初始化网络并配置网络 |
| 计费管理 | 记录网络资源使用情况 |
| 性能管理 | 评价系统资源运行状况和通信效率 |
| 网络安全管理 | 管理授权机制、访问控制、加密和密钥 |

#### 二、网络管理的一般模型

课件中的网络管理模型包含：

- 管理站（Management Station）。
- 被管设备（Managed Device）。
- 管理程序。
- 代理程序（Agent）。
- 网管协议。

管理站也称网络运行中心NOC（Network Operations Center），是网络管理系统的核心。

课件特别区分：

- **Manager（管理者）**：管理站硬件或管理程序软件，不是指网络管理员这个人。
- **Administrator（网络管理员）**：负责网络管理的人员。

#### 三、被管对象与代理

**被管对象（Managed Object）**：被管设备及其软件中能够被管理的对象。一个设备可能包含多个被管对象。

**代理（Agent）**：

- 在每个被管设备中运行。
- 与管理站中的管理程序通信。
- 根据管理程序的命令和控制，在被管设备上采取本地行动。

**网络管理协议**规定管理程序与代理程序之间如何通信。注意：网管协议本身不直接管理网络，而是提供管理者与代理之间的通信规则。

#### 四、SNMP的基本功能

SNMP（Simple Network Management Protocol，简单网络管理协议）中：

- 管理程序运行SNMP客户程序，向代理程序发送请求或命令。
- 代理程序运行SNMP服务器程序，返回响应或执行相应动作。
- 一个或少数几个管理程序可以与许多代理程序交互。

SNMP的基本功能：

1. 监视网络性能。
2. 检测和分析网络差错。
3. 配置网络设备。

课件指出，整个系统必须有一个管理站。如果某个网络元素使用其他网管协议，可以通过委托代理（proxy agent）提供协议转换和过滤操作。

#### 五、SNMP网络管理的三个组成部分

SNMP网络管理由三部分组成：

1. SNMP本身。
2. 管理信息结构SMI（Structure of Management Information）。
3. 管理信息库MIB（Management Information Base）。

SNMP负责定义管理站与代理之间交换的分组格式，分组中包含代理内对象（变量）的名称及其状态（值），并提供读取和改变这些数值的操作。

### 6.7.2 管理信息结构 SMI（PDF 87～89页）

SMI规定网络管理信息的通用规则，主要包括：

1. 被管对象应当如何命名。
2. 被管对象可以使用哪些数据类型，包括范围和长度。
3. 管理数据在网络上传输时应当如何编码。

SMI的目标是保证网络管理数据的语法和语义没有歧义。

课件强调：SMI不负责定义一个实体应管理多少对象，也不负责定义具体的被管对象及其对象值之间的关联。

#### 对象命名树

所有被管对象都必须在命名树上。

课件给出的MIB-2路径：

**1.3.6.1.2.1**

对应：

**iso.org.dod.internet.mgmt.mib-2**

例如：

- system：1
- interfaces：2
- ip：4
- icmp：5
- tcp：6
- udp：7

课件举例的对象ipInReceives，其对象标识符为：

**1.3.6.1.2.1.4.3**

### 6.7.3 管理信息库 MIB（PDF 87、90～91页）

MIB中保存被管对象的控制信息和状态信息，并规定对象及其类型。

- 管理程序使用MIB中的信息管理网络。
- 管理程序可以读取或重新设置MIB中的值。
- **只有MIB中定义的对象才是SNMP能够管理的对象。**

课件列举的MIB-2信息类别：

| 类别 | 标号 | 信息内容 |
|---|---:|---|
| system | 1 | 主机或路由器的操作系统 |
| interfaces | 2 | 各种网络接口 |
| address translation | 3 | 地址转换，例如ARP映射 |
| ip | 4 | IP软件 |
| icmp | 5 | ICMP软件 |
| tcp | 6 | TCP软件 |
| udp | 7 | UDP软件 |
| egp | 8 | EGP软件 |

常见MIB变量：

| MIB变量 | 所属类别 | 含义 |
|---|---|---|
| sysUpTime | system | 距上次重启动的时间 |
| ifNumber | interfaces | 网络接口数 |
| ifMtu | interfaces | 特定接口的MTU |
| ipDefaultTTL | ip | IP生存时间字段使用的值 |
| ipInReceives | ip | 接收到的数据报数目 |
| ipForwDatagrams | ip | 转发的数据报数目 |
| ipOutNoRoutes | ip | 路由选择失败的数目 |
| ipReasmOKs | ip | 重装的数据报数目 |
| ipFragOKs | ip | 分片的数据报数目 |
| ipRoutingTable | ip | IP路由表 |
| icmpInEchos | icmp | 收到的ICMP回送请求数目 |
| tcpRtoMin | tcp | TCP允许的最小重传时间 |
| tcpMaxConn | tcp | 允许的最大TCP连接数目 |
| tcpInSegs | tcp | 已收到的TCP报文段数目 |
| udpInDatagrams | udp | 已收到的UDP数据报数目 |

### 6.7.4 SNMP的协议数据单元和报文（PDF 92～95页）

#### 一、读操作与写操作

SNMP有两种基本管理功能：

- **Get读操作**：检测被管对象的状态。
- **Set写操作**：改变被管对象的状态。

#### 二、探询操作（Polling）

SNMP管理进程定时向被管理设备周期性发送探询信息。

优点：

- 系统相对简单。
- 能限制网络中管理信息产生的通信量。

缺点：

- 不够灵活。
- 可管理的设备数量不能太多。
- 仍然有一定的管理开销。

#### 三、陷阱 Trap

SNMP允许代理不经过管理站询问，就主动发送某些信息，这些信息称为陷阱（Trap）。

工作过程：

1. 代理检测到被管对象发生事件。
2. 代理检查对应门限值。
3. 只有达到某些门限值的事件才报告给管理进程。

优点：

- 只在达到一定条件的事件发生时才发送信息。
- 陷阱报文比较简单，占用字节较少。

**探询用于周期性监视，Trap用于主动报告达到条件的特殊事件。** 两者结合可以进行持续监视并及时报告重要变化。

#### 四、SNMP使用UDP

课件指出SNMP使用无连接的UDP：

| 端口 | 作用 |
|---|---|
| UDP 161 | 被管设备上的代理程序接收Get或Set报文，并发送响应 |
| UDP 162 | 管理程序接收各代理发送的Trap报文 |

#### 五、课件列出的PDU类型

> 课件该表标题写作“SNMPv1定义的PDU类型”，但表中同时列有SNMPv2Trap等项目；本笔记保留课件列项，课件未进一步解释这些PDU的版本归属。

| PDU编号 | PDU名称 | 用途 |
|---|---|---|
| 0（A0） | GetRequest | 查询一个或一组变量的值 |
| 1（A1） | GetNextRequest | 读取MIB树上的下一个变量，可重复执行 |
| 2（A2） | Response | 返回响应 |
| 3（A3） | SetRequest | 设置一个或多个变量的值 |
| 5（A5） | GetBulkRequest | 从代理读取较大数据块 |
| 6（A6） | InformRequest | 管理者之间的信息请求 |
| 7（A7） | SNMPv2Trap | 代理向管理者报告异常事件 |
| 8（A8） | Report | 管理者之间报告某些差错 |

课件第95页给出了SNMP报文的封装层次：IP数据报中承载UDP数据报，UDP数据报中承载SNMP报文。报文内容包括版本、安全参数、上下文信息、PDU类型、请求ID、差错状态、差错索引和变量绑定等字段。

## 三、本章易混淆点

1. **域名与IP地址**：域名是便于人使用的逻辑名称，DNS负责把域名解析为IP地址。
2. **根域名服务器与本地域名服务器**：根服务器通常告诉查询方下一步找哪个顶级域名服务器；主机通常先向本地域名服务器发出请求。
3. **递归查询与迭代查询**：递归由被请求方继续查询并返回最终结果；迭代由原查询方根据提示继续找下一台服务器。
4. **FTP控制连接与数据连接**：控制连接传命令，数据连接传文件；控制连接通常持续整个会话，数据连接随传输建立和释放。
5. **TELNET与NVT**：TELNET负责远程终端通信，NVT是统一客户端与服务器数据表示的中间格式。
6. **WWW与互联网**：WWW不是一种特殊网络，而是运行在互联网上的分布式超媒体系统。
7. **URL、HTTP与HTML**：URL定位资源；HTTP规定浏览器与服务器如何交换请求和响应；HTML描述网页文档结构。
8. **HTTP与TCP**：HTTP使用TCP可靠传输，但HTTP自身是无状态的；持续连接是TCP连接的复用方式。
9. **HTTP请求报文与响应报文**：请求报文开始行是请求行；响应报文开始行是状态行。
10. **SMTP与POP3/IMAP**：SMTP负责发送邮件，POP3或IMAP负责读取邮件。
11. **邮件信封与邮件内容**：信封用于传输和投递，内容是用户读取时看到的首部与主体。
12. **DHCP四步交互**：Discover、Offer、Request、ACK；不要把服务器提供地址和客户正式请求使用地址的步骤混为一谈。
13. **DHCP端口**：服务器UDP 67，客户UDP 68。
14. **SMI与MIB**：SMI规定命名、类型和编码规则；MIB保存被管理的对象及其信息。
15. **SNMP探询与Trap**：探询由管理站周期性发起；Trap由代理在满足事件条件时主动报告。

## 四、复习时优先串起的主线

- **DNS**：输入域名 → 本地域名服务器 → 根/TLD/权限服务器 → 得到IP地址 → 缓存结果。
- **FTP**：控制连接建立 → 发送传送命令 → 建立数据连接 → 传送文件 → 关闭数据连接。
- **WWW**：URL定位资源 → 浏览器发送HTTP请求 → 服务器返回HTTP响应 → 浏览器按HTML等文档内容显示页面。
- **电子邮件**：用户代理撰写 → SMTP发送 → 邮件服务器保存与转送 → POP3/IMAP读取。
- **DHCP**：Discover → Offer → Request → ACK → 租用期内使用并续租。
- **SNMP**：管理站通过代理访问MIB → Get读取、Set修改 → 周期探询或Trap报告事件。
