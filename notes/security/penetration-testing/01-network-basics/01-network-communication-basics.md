# 知识地图

```text
访问网站
├─ 域名
│  └─ DNS 解析
├─ IP 地址
│  └─ 定位目标主机
├─ 端口
│  └─ 定位目标服务
└─ TCP / UDP
   ├─ TCP：连接、可靠、有序
   │  ├─ 三次握手：SYN → SYN+ACK → ACK
   │  └─ 四次挥手：FIN → ACK → FIN → ACK
   └─ UDP：简单、实时性优先

一条 TCP 连接
└─ 源 IP:源端口 → 目标 IP:目标端口
   └─ 入站 / 出站取决于观察主机

内网访问互联网
└─ 私有 IP → NAT 地址/端口映射 → 公网 IP
```

# 一、网络通信的基本链条

访问一个网站时，可以粗略理解为：

域名
↓
DNS
↓
IP 地址
↓
端口
↓
TCP / UDP
↓
对应的网络服务

例如：

example.com
↓ DNS
某服务器 IP
↓
服务器IP:443
↓
HTTPS 服务

核心记忆：

- IP：找主机
- Port：找服务
- TCP / UDP：决定数据如何传输
- DNS：把域名解析成 IP

---

# 二、域名与 DNS

## 1. 域名

域名是方便人类记忆的网络名称，例如：

github.com
www.example.com

相比直接记忆一串 IP 地址，人更容易记住域名。

域名本身不能代替 IP 完成底层 IP 网络中的寻址，因此进行网络通信之前，通常需要先得到它对应的 IP 地址。

---

## 2. DNS

DNS：

Domain Name System

中文：

域名系统

主要作用：

把域名解析成对应的 IP 地址。

例如：

example.com
↓ DNS
93.x.x.x

之后计算机才能根据 IP 地址找到目标服务器。

可以把 DNS 暂时类比成：

网络电话簿

名字 → 域名
电话号码 → IP 地址

---

# 三、IP 地址

IP 地址主要用于：

定位网络中的目标主机或网络接口。

例如：

192.168.1.20

表示网络中的某个地址。

简单记忆：

IP = 找哪台主机

---

# 四、端口 Port

仅仅找到一台主机还不够。

一台服务器可能同时运行：

- Web 服务
- SSH 服务
- 数据库
- 游戏服务器
- 其他网络程序

所以还需要端口来区分不同网络服务。

例如：

10.0.0.8:22

其中：

10.0.0.8
→ 目标主机

22
→ 目标主机上的某个网络服务

简单记忆：

IP = 找主机
端口 = 找服务

---

# 五、端口号范围

TCP 和 UDP 的端口号都是 16 位。

因此端口号范围：

0 ~ 65535

因为：

2^16 = 65536

从 0 开始编号，所以最大为 65535。

---

# 六、监听端口

监听并不是“被攻击者监听”的意思。

监听是操作系统中的正常网络概念。

例如：

SSH 服务监听 TCP 22

意思是：

SSH 程序告诉操作系统：

如果有连接请求发送到 TCP 22 端口，就把对应通信交给我处理。

因此：

监听端口
=
某个网络服务正在等待对应端口上的通信。

---

# 七、开放端口

如果一个端口处于开放状态，可以粗略理解为：

这个端口上存在能够接受网络通信的程序或服务。

例如：

22 open
80 open
443 open

可能分别对应：

22 → SSH
80 → HTTP
443 → HTTPS

但必须注意：

端口号 ≠ 必然对应某种服务

例如：

22 是 SSH 的默认端口。

但管理员完全可以让 SSH 使用：

2222

因此：

22 open

只能说明：

22 端口存在可接受通信的服务。

不能仅凭端口号 100% 判断服务类型。

---

# 八、默认端口

常见默认端口：

22 → SSH
80 → HTTP
443 → HTTPS
53 → DNS

但：

默认端口 ≠ 强制端口

例如 HTTPS 完全可以运行在：

8443

因此：

443 通常是 HTTPS

但：

443 不一定就是 HTTPS。

---

# 九、TCP 与 UDP

TCP 和 UDP 并不是“端口的两种格式”。

它们是两种不同的传输层协议。

完整的网络通信需要考虑：

IP + 端口 + 传输层协议

例如：

192.168.1.10:443 / TCP

表示：

通过 TCP 协议，与 192.168.1.10 主机上的 443 端口进行通信。

---

# 十、TCP

TCP：

Transmission Control Protocol

核心特点：

- 面向连接
- 提供可靠传输
- 保证数据顺序
- 可以发现部分数据丢失
- 可以进行重传

TCP 的可靠并不是：

网络永远不会丢包。

而是：

即使网络中出现丢包、乱序等情况，TCP 会通过自身机制尽量让应用最终得到正确、有序的数据。

常见机制：

- Seq 序列号
- ACK 确认
- 重传
- 排序

---

# 十一、UDP

UDP：

User Datagram Protocol

特点：

- 不需要像 TCP 一样建立可靠连接
- 协议机制简单
- 额外开销较少
- UDP 本身不保证数据一定到达
- UDP 本身不保证数据按照顺序到达
- UDP 本身不负责重传

因此 UDP 适合一些强调实时性的场景。

例如实时语音：

某一小段声音数据丢失后，如果等待旧数据重传，反而可能造成更严重的延迟。

因此某些实时程序可能选择：

丢掉已经过时的数据，继续处理最新数据。

注意：

使用 UDP 并不代表应用程序完全不能实现可靠机制。

应用可以在 UDP 之上自行加入额外机制。

---

# 十二、TCP 端口和 UDP 端口

TCP 和 UDP 各自拥有自己的端口空间。

因此：

TCP 53

和：

UDP 53

不是完全相同的通信入口。

虽然数字相同，但使用的是两种不同的传输层协议。

DNS 就可能使用：

UDP 53

也可以使用：

TCP 53

---

# 十三、TCP 三次握手

TCP 在正式传输数据之前需要建立连接。

基本过程：

SYN
↓
SYN + ACK
↓
ACK

---

## 第一次

客户端 → 服务器

SYN

含义：

客户端希望建立 TCP 连接。

---

## 第二次

服务器 → 客户端

SYN + ACK

含义：

服务器收到了客户端的连接请求，并同意建立连接。

---

## 第三次

客户端 → 服务器

ACK

含义：

客户端确认已经收到服务器的回应。

至此 TCP 连接建立。

---

# 十四、SYN 与 ACK

SYN：

Synchronize

主要用于 TCP 建立连接。

可以粗略理解为：

我要与你建立连接。

ACK：

Acknowledgment

表示确认。

可以粗略理解为：

你之前发送的信息我收到了。

---

# 十五、TCP Seq 与 ACK

TCP 会使用序列号：

Seq

来标识传输数据的位置。

ACK 则会告诉对方：

自己接下来期待收到哪个序列号。

简单例子：

已经连续收到：

Seq 1
Seq 2
Seq 3

发送：

ACK 4

表示：

4 之前的数据已经连续收到，接下来期待从 4 开始的数据。

注意：

真实 TCP 中 Seq 主要对字节进行编号，并不是简单地给每个数据包编号。

核心理解：

Seq
→ 数据的位置

ACK
→ 下一步期待收到的位置

如果数据发生丢失，TCP 可以利用这些信息发现问题，并进行相应处理或重传。

---

# 十六、TCP 四次挥手

TCP 是双向通信。

一方不再发送数据，不代表另一方的数据也已经发送完毕。

因此关闭 TCP 连接通常需要双方分别关闭自己的发送方向。

过程：

FIN
↓
ACK
↓
FIN
↓
ACK

---

## 第一次

客户端 → 服务器

FIN

表示：

客户端的数据已经发送完毕，准备关闭自己的发送方向。

---

## 第二次

服务器 → 客户端

ACK

表示：

服务器已经知道客户端准备停止发送数据。

此时服务器仍然可能继续发送剩余数据。

---

## 第三次

服务器 → 客户端

FIN

表示：

服务器自己的数据也已经发送完毕。

---

## 第四次

客户端 → 服务器

ACK

表示：

客户端确认收到服务器的关闭请求。

连接随后结束。

---

# 十七、FIN

FIN：

Finish

可以粗略理解为：

我这边的数据已经发送完了，准备结束这一方向的通信。

因此目前需要记住三个重要 TCP 标志：

SYN
→ 建立连接

ACK
→ 确认收到

FIN
→ 准备结束连接

---

# 十八、一条 TCP 连接如何区分

一条 TCP 连接通常可以通过以下四个信息区分：

源 IP
+
源端口
+
目标 IP
+
目标端口

例如：

192.168.1.10:50001
→
10.0.0.8:22

其中：

192.168.1.10
→ 源 IP

50001
→ 源端口

10.0.0.8
→ 目标 IP

22
→ 目标端口

---

# 十九、为什么多个客户端可以同时访问一个 443 端口

服务器可能一直监听：

TCP 443

大量客户端都可以访问它。

例如：

192.168.1.10:50001 → 10.0.0.8:443

192.168.1.10:50002 → 10.0.0.8:443

虽然目标：

IP 一样
端口一样

但源端口不同：

50001
50002

因此操作系统仍然能够区分两条不同的 TCP 连接。

---

# 二十、客户端端口与服务器端口

服务器通常会监听一个比较固定的服务端口。

例如：

SSH → 22

客户端进行连接时，自己这一侧通常还需要一个临时端口。

例如：

192.168.1.10:52736
→
10.0.0.8:22

其中：

52736
→ 客户端临时使用的源端口

22
→ SSH 服务器监听的目标端口

---

# 二十一、源 IP 与目标 IP

数据包：

192.168.1.20:53000
→
8.8.8.8:53

其中：

源 IP：
192.168.1.20

源端口：
53000

目标 IP：
8.8.8.8

目标端口：
53

格式：

源IP:源端口
→
目标IP:目标端口

---

# 二十二、源和目标会随着数据方向变化

客户端发送：

192.168.1.20:53000
→
8.8.8.8:53

服务器返回：

8.8.8.8:53
→
192.168.1.20:53000

因此：

源和目标不是一台机器永久固定的身份。

而是：

谁正在发送数据，谁就是源。

数据要发送给谁，谁就是目标。

---

# 二十三、入站与出站

入站和出站必须明确：

站在哪台机器的视角。

假设：

我的电脑
→
服务器

站在我的电脑角度：

发送出去
=
Outbound
=
出站

服务器返回数据：

服务器
→
我的电脑

站在我的电脑角度：

进入电脑
=
Inbound
=
入站

---

# 二十四、防火墙中的入站与出站规则

Windows 防火墙常见：

Inbound Rules
=
入站规则

主要控制：

网络中的其他设备访问本机时，哪些通信允许进入。

Outbound Rules
=
出站规则

主要控制：

本机主动向外进行网络通信时，哪些通信允许出去。

---

# 二十五、内网 IP / 私有 IP

常见私有 IP 地址范围：

10.0.0.0/8

172.16.0.0 ~ 172.31.255.255

192.168.0.0/16

例如：

192.168.1.20

这种地址可以在不同局域网中重复使用。

例如：

家庭 A：

192.168.1.20

家庭 B：

192.168.1.20

两者并不冲突。

因为：

它们属于不同的局域网。

---

# 二十六、公网 IP

公网 IP 可以用于互联网中的路由和通信。

内网设备自己的：

192.168.x.x

通常不会直接作为它在公网中的地址。

网站看到的地址，往往是网络经过 NAT 后所使用的公网地址。

---

# 二十七、NAT

NAT：

Network Address Translation

中文：

网络地址转换

核心作用：

在内网地址与对外使用的公网地址之间进行转换和映射。

例如：

电脑：

192.168.1.20:50001

经过 NAT 后，对外可能变成：

公网IP:62001

服务器看到的是：

公网IP:62001

NAT 设备会记录映射关系。

当服务器返回数据时：

服务器
↓
公网IP:62001
↓ NAT
192.168.1.20:50001

最终把数据交回真正发起通信的内网设备。

---

# 二十八、NAT 的重要意义

NAT 可以让：

多个使用私有 IP 的内网设备

通过：

一个或少量公网 IP

访问互联网。

因此不能简单理解成：

内网 IP 永久变成公网 IP。

更准确的是：

在网络通信过程中进行地址和端口的映射与转换。

# 三十、今日必须掌握

1. DNS 用于把域名解析成 IP。

4. TCP 提供面向连接、可靠、有序的数据传输。

6. TCP 三次握手：

SYN
→
SYN + ACK
→
ACK

7. TCP 常通过 Seq、ACK、重传等机制提高可靠性。

8. TCP 四次挥手：

FIN
→
ACK
→
FIN
→
ACK

9. 一条 TCP 连接通常可通过：

源 IP
+
源端口
+
目标 IP
+
目标端口

进行区分。

10. 入站和出站必须站在某台主机的视角判断。
