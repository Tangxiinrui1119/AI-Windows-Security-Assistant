# 一、子网掩码与 CIDR

## 1. 子网掩码的作用

IP 地址本身不能单独告诉计算机“网络部分到哪里结束”。

子网掩码用于区分：

- 网络部分
- 主机部分

例如：

    IP：192.168.1.10
    子网掩码：255.255.255.0

可以粗略理解为：

    192.168.1 | 10
    网络部分    主机部分

因此在这个例子中：

    192.168.1.20

与本机处于同一网段，而：

    192.168.2.20

不属于同一网段。

子网掩码并不是“说明文字”，而会直接参与系统的路由判断。

---

## 2. 为什么不能只看 IP

例如两台主机：

    192.168.1.10
    192.168.1.200

如果掩码为：

    255.255.255.0 = /24

它们属于同一网段。

但如果掩码为：

    255.255.255.128 = /25

它们可能属于不同子网。

因此：

> 是否同一网段不能只靠肉眼比较 IP，必须结合子网掩码。

---

## 3. CIDR /xx

CIDR 前缀长度是子网掩码的另一种表示方式。

例如：

    /16 = 255.255.0.0
    /24 = 255.255.255.0
    /25 = 255.255.255.128

“/xx”中的数字表示：

> 子网掩码二进制中前面连续 1 的数量。

例如：

    255.255.255.0
    =
    11111111.11111111.11111111.00000000

前面共有 24 个 1，因此写成：

    /24

---

## 4. 子网判断的本质

计算机不是靠肉眼看前三段是否相同，而是使用 IP 与子网掩码做按位 AND 运算，得到网络地址。

例如：

    192.168.1.10/25
    网络地址：192.168.1.0/25

而：

    192.168.1.200/25
    网络地址：192.168.1.128/25

网络地址不同，因此不属于同一子网。

# 二、直连网段

如果目标地址属于本机直接连接的网段，则路由表会显示类似：

    10.153.0.0    255.255.0.0    在链路上

等价于：

    10.153.0.0/16 → 在链路上

“在链路上”表示：

> 该目标网段与本机直接相连，不需要先经过另一个路由器作为下一跳。

例如本机：

    10.153.229.208/16

目标：

    10.153.100.50

目标属于：

    10.153.0.0/16

因此可以走直连路由。

---

# 三、路由表

## 1. 路由表解决什么问题

路由表可以理解为计算机的“送货规则表”。

它回答：

> 去某个目标 IP，应该从哪条路、哪个接口、哪个下一跳出去？

Windows 可使用：

    route print

查看 IPv4 / IPv6 路由表。

---

## 2. 路由条目中的 /xx

在路由表中：

    10.153.0.0/16

表示：

> 这条路由负责匹配前 16 位符合 10.153.0.0/16 的目标地址。

例如：

    10.153.1.20
    10.153.100.50
    10.153.229.208

都能匹配该路由。

而：

    10.154.1.20

不能匹配。

因此：

> 在路由表中，“/xx”规定了这条规则负责多大的目标地址范围。

---

# 四、最长前缀匹配

当一个目标 IP 同时能匹配多条路由时：

> 优先选择前缀长度更长、规则更具体的路由。

例如：

    0.0.0.0/0
    10.153.0.0/16

访问：

    10.153.100.50

两条都能匹配，但：

    /16 比 /0 更具体

因此选择：

    10.153.0.0/16

这称为：

> Longest Prefix Match，最长前缀匹配。

---

# 五、metric / 跃点数

Windows 路由表中的 metric 可以理解为：

> 路由成本 / 优先成本。

数字越小，在其他条件相同时越优先。

但必须牢记：

> 先比较前缀长度，再比较 metric。

例如：

    0.0.0.0/0      metric 0
    10.153.0.0/16  metric 291

访问：

    10.153.100.50

仍然选择 /16，而不是 metric 0 的 /0。

只有路由同样具体时，metric 才成为主要比较依据。

例如：

    0.0.0.0/0  metric 35
    0.0.0.0/0  metric 0

这时两条前缀相同，优先 metric 0。

---

# 六、默认路由与默认网关

## 1. 默认路由

IPv4 中：

    0.0.0.0/0

称为默认路由。

它的含义可以理解为：

> 如果没有更具体的路由匹配目标，就走这条兜底路线。

---

## 2. 默认网关

例如：

    0.0.0.0/0 → 192.168.1.1

则：

    192.168.1.1

就是该默认路由对应的默认网关。

当目标不属于本机直连网段，并且没有更具体路由时，数据会先交给默认网关。

---

## 3. 默认网关不等于所有跨网段通信的下一跳

这是今日重点易错点。

例如：

    172.16.0.0/12 → 网关 192.168.1.254
    0.0.0.0/0     → 网关 192.168.1.1

访问：

    172.16.5.20

会匹配更具体的：

    172.16.0.0/12

因此下一跳是：

    192.168.1.254

而不是默认网关：

    192.168.1.1

结论：

> 路由表指定谁是下一跳，就把数据交给谁；只有没有更具体路由时才使用默认路由/默认网关。

---

# 七、下一跳

“最终目标”和“下一跳”必须分开。

例如：

    最终目标 IP：203.0.113.80
    默认网关：192.168.50.1

本机第一跳可能是：

    最终目标 IP：203.0.113.80
    下一跳 IP：192.168.50.1

最终目标并没有变成网关。

网关只是帮助数据继续向最终目标转发。

---

# 八、ARP

## 1. ARP 的作用

ARP：

Address Resolution Protocol

核心作用：

> 在 IPv4 局域网通信中，根据下一跳 IPv4 地址解析对应的 MAC 地址。

简单记忆：

    DNS：域名 → IP
    ARP：IPv4 → MAC

二者不要混淆。

---

## 2. 同网段时 ARP 查谁

本机：

    192.168.50.23/24

目标：

    192.168.50.77

因为目标在直连网段，所以：

    ARP 查询 192.168.50.77 的 MAC

数据可以直接交给目标主机。

---

## 3. 跨网段时 ARP 查谁

本机要访问：

    203.0.113.80

路由表决定下一跳：

    192.168.50.1

那么 ARP 查询：

    192.168.50.1 的 MAC

而不是查询：

    203.0.113.80 的 MAC

因此可以记：

> ARP 查的是“这一跳要交给谁”，不一定是最终目标。

---

# 九、ARP 缓存

Windows 可以使用：

    arp -a

查看 ARP 缓存。

例如：

    10.153.0.1 → 5c-64-7a-ca-42-07

表示：

> 本机已经知道 10.153.0.1 对应的 MAC 地址。

如果缓存中已有有效记录，通常不需要每次重新广播询问。

动态 ARP 条目会随时间过期或更新。

---

# 十、广播 MAC

广播 MAC：

    ff-ff-ff-ff-ff-ff

表示：

> 当前二层广播域中的设备都接收这一个帧。

例如 DHCP 客户端刚接入网络、还不知道 DHCP 服务器是谁时，就可以通过广播寻找 DHCP 服务。

---

# 十一、DHCP

DHCP：

Dynamic Host Configuration Protocol

中文：

动态主机配置协议

作用：

> 自动为客户端提供网络配置。

常见内容包括：

- IPv4 地址
- 子网掩码
- 默认网关
- DNS 服务器地址
- 租约时间

---

## 1. DHCP 不一定与客户端在同一台机器上

普通电脑通常是：

> DHCP Client

真正分配网络配置的是：

> DHCP Server

也不需要“每个网段必须放一台独立 DHCP 服务器”。

大型网络中可以通过：

> DHCP Relay / DHCP 中继

让客户端访问位于其他网段的 DHCP 服务。

---

## 2. DORA

DHCP 获取地址的典型过程：

    Discover
    ↓
    Offer
    ↓
    Request
    ↓
    ACK

可以理解为：

    客户端：谁能给我网络配置？
    DHCP：我可以给你这个地址。
    客户端：我要这个。
    DHCP：确认，给你使用。

---

## 3. 为什么一开始要广播

客户端刚接入网络时：

- 还没有正常 IPv4 地址
- 不知道 DHCP 服务器 IP
- 无法直接定向发送

因此最初可以广播：

    源 IPv4：0.0.0.0
    目标 IPv4：255.255.255.255
    目标 MAC：ff-ff-ff-ff-ff-ff

寻找 DHCP 服务。

---

## 4. DHCP 不负责普通数据转发

DHCP 主要负责分配和维护网络配置。

获得配置后，访问其他目标时主要依靠：

    目标 IP
    ↓
    路由表
    ↓
    下一跳
    ↓
    ARP（如需要）

DHCP 不参与每一次普通数据包的路由转发。

但租约即将到期时，客户端还会与 DHCP 交互进行续租。

---

# 十二、DNS 服务器与 DHCP 的关系

DNS 的“域名 → IP”功能已经在网络基础补齐 01 学习。

本节新增联系：

> DHCP 通常会告诉客户端应该使用哪个 DNS 服务器。

计算机可能先查询本地 DNS 缓存。

若本地无记录，再向配置好的 DNS 服务器查询。

因此在网络配置中看到：

    DNS Server：x.x.x.x

表示：

> 本机进行 DNS 查询时可使用的 DNS 服务地址。

---

# 十三、ICMP

ICMP：

Internet Control Message Protocol

主要用于传递：

- 网络控制信息
- 状态信息
- 错误信息

常见工具：

- ping
- tracert

都与 ICMP 密切相关。

---

# 十四、ping

Windows：

    ping <目标 IP 或域名>

ping 常用：

> ICMP Echo Request

向目标发送探测。

目标如果能够并允许响应，则返回：

> ICMP Echo Reply

因此 ping 成功通常能说明：

> 当前存在可用的往返通信路径，并成功收到了 ICMP Echo Reply。

---

## ping 不通不等于目标关机

例如：

    Request timed out

只能说明：

> 没有收到预期的 ICMP Echo Reply。

不能直接推出：

> 目标一定关机或不存在。

其他可能原因：

- 目标主机防火墙过滤 ICMP
- 中间网络设备过滤相关 ICMP
- 网络故障
- 返回路径异常
- 目标配置为不响应 ping

这是安全分析中非常重要的判断原则。

---

# 十五、TTL

TTL：

Time To Live

虽然名称是“生存时间”，但在 IP 转发中可以理解为：

> 数据包还能经过多少个路由器。

每经过一个路由器：

    TTL = TTL - 1

当 TTL 变为 0：

- 路由器丢弃数据包
- 通常返回 ICMP Time Exceeded

TTL 的重要目的之一：

> 防止数据包因为路由环路而永远在网络里转发。

---

# 十六、tracert

Windows：

    tracert <目标 IP 或域名>

tracert 的核心思路：

> 主动发送一系列探测包，并故意逐步增大 TTL。

第一次：

    TTL = 1

第一跳路由器：

    1 → 0

于是返回：

    ICMP Time Exceeded

本机得到第一跳 IP。

第二次：

    TTL = 2

第一跳：

    2 → 1

第二跳：

    1 → 0

第二跳返回 ICMP Time Exceeded。

于是得到第二跳 IP。

然后继续：

    TTL = 3
    TTL = 4
    TTL = 5
    ...

逐步推测整条路径上的路由节点。

---

## tracert 中 * * * 的含义

例如：

    1  192.168.1.1
    2  10.20.0.1
    3  * * *
    4  61.x.x.x
    5  目标

第三跳出现：

    * * *

不代表：

> 第三台路由器一定坏了。

如果第四、第五跳仍然出现，说明数据仍然能够继续向后转发。

更可能的解释包括：

- 该设备不返回相应 ICMP 响应
- 防火墙过滤响应
- 响应超时
- 设备配置了相关限制

因此：

> “不回复探测”与“不能继续转发数据”是两件不同的事。

# 十七、今日实机命令

## 1. 查看网络配置

    ipconfig

重点观察：

- IPv4 地址
- 子网掩码
- 默认网关

本次实机 WLAN 配置：

    IPv4：10.153.229.208
    子网掩码：255.255.0.0
    默认网关：10.153.0.1

因此：

    10.153.229.208/16

其直连网段为：

    10.153.0.0/16

---

## 2. 查看路由表

    route print

本次实机同时存在：

    WLAN 默认路由
    Meta Tunnel 默认路由

并观察到：

    10.153.0.0/16 → WLAN
    0.0.0.0/0 → WLAN
    0.0.0.0/0 → Meta Tunnel

通过该实例理解：

- 最长前缀匹配
- 相同前缀再比较 metric
- 虚拟隧道接口可以改变普通互联网流量的出口选择

---

## 3. 查看 ARP 缓存

    arp -a

本次观察到：

    10.153.0.1 → 5c-64-7a-ca-42-07

说明：

> 本机已经缓存 WLAN 默认网关 IPv4 与 MAC 的对应关系。

# 十八、完整通信判断流程

当已经知道目标 IP 后，可以按下面流程分析：

    目标 IP
    ↓
    查路由表
    ↓
    找出所有能匹配的路由
    ↓
    先做最长前缀匹配
    ↓
    若同样具体，再比较 metric
    ↓
    得到出口与下一跳
    ↓
    如果是普通局域网二层通信且缺少 MAC
    ↓
    ARP 查询下一跳 IPv4 对应 MAC
    ↓
    发出数据

如果用户最初输入的是域名，则在前面还有：

    域名
    ↓
    DNS 查询
    ↓
    得到目标 IP

如果设备刚接入网络、还没有网络配置，则更前面还有：

    接入网络
    ↓
    DHCP
    ↓
    获得 IP / 掩码 / 网关 / DNS
    ↓
    开始正常通信

# 十九、重点易错点

## 误区 1：子网掩码只是用来“标注” IP

错误。

子网掩码实际参与：

- 网络地址计算
- 本地/远程判断
- 路由生成与选择

---

## 误区 2：看到 IP 前三段相同就一定同网段

错误。

必须结合子网掩码 / CIDR。

---

## 误区 3：路由选择先看 metric

错误。

正确顺序：

    先最长前缀匹配
    ↓
    一样具体时再比较 metric

---

## 误区 4：跨网段永远走默认网关

错误。

如果存在更具体路由，例如：

    172.16.0.0/12 → 192.168.1.254

则访问该网段时应走：

    192.168.1.254

而不是默认网关。

---

## 误区 5：ARP 永远查询最终目标的 MAC

错误。

ARP 查询的是：

> 当前本地链路上真正需要交付的下一跳 IPv4 所对应的 MAC。

同网段：

    下一跳 = 最终目标

跨网段：

    下一跳通常 = 某个路由器

---

## 误区 6：ARP 是域名解析

错误。

    DNS：域名 → IP
    ARP：IPv4 → MAC

---

## 误区 7：ping 不通就代表目标关机

错误。

ping 不通只能说明：

> 没收到预期的 ICMP Echo Reply。

---

## 误区 8：tracert 某一跳 * * * 就代表那里断网

错误。

后续跳数仍能出现时，说明该节点仍可能正常转发，只是不返回可见的探测响应。
