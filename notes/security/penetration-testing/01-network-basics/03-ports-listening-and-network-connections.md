# 知识地图

```text
网络通信
├─ IP 地址：定位主机 / 网络接口
├─ 端口：定位通信入口
│  └─ 客户端 IP:临时端口 ↔ 服务器 IP:服务端口
├─ TCP 状态
│  ├─ LISTENING：等待连接请求

├─ 本地监听地址
│  ├─ 0.0.0.0：本机所有 IPv4 接口
│  └─ 127.0.0.1：本机回环地址

   └─ 协议 → 本地地址 → 远程地址 → 状态 → PID

与 Windows 主机安全的衔接
网络连接 → PID → 进程名 → 路径 → PPID → CommandLine
```

# 一、端口与客户端 / 服务器

## 1. 为什么有 IP 还需要端口

一台主机可以同时运行浏览器、Web 服务、数据库等多个网络程序。

IP 帮助找到主机或接口，端口帮助操作系统把通信交给对应的程序。

```text
IP：找哪台主机 / 哪个接口
端口：找哪个通信入口
协议：TCP 或 UDP
```

TCP 和 UDP 各有自己的端口空间；TCP 443 与 UDP 443 是不同的通信入口。

## 2. 客户端也需要端口

服务器通常监听一个比较固定的服务端口。

客户端主动发起连接时，操作系统通常为它分配一个临时端口。例如一次 TCP 通信：

```text
客户端                          服务器
192.168.1.20:53000  ↔  203.0.113.80:443
             ↑                     ↑
          临时端口               服务端口
```

这里的 IP、端口和后文 PID 都是教学示例，不是本次实机采集结果。

服务器返回数据时，目标是客户端的 `192.168.1.20:53000`。连接建立后双方都可以发送和接收数据。

常见约定：22 对应 SSH，80 对应 HTTP，443 对应 HTTPS。但程序可以配置其他端口，不能只凭 443 就确定服务类型或安全性。

## 3. 客户端与服务器是通信角色

主动请求服务的一侧通常叫客户端，提供服务、等待请求的一侧通常叫服务器。

同一台电脑可以访问远程网站，也可以运行本地服务，因此可以同时承担两种角色。

多条 TCP 连接可以使用同一个服务器端口；操作系统根据两端 IP 和端口区分连接。

# 二、LISTENING 与 ESTABLISHED

| 状态 | 含义 | 可以判断什么 |
|---|---|---|
| `LISTENING` | 本机某个 TCP 入口正在等待连接请求 | 有程序在该地址和端口监听 |
| `ESTABLISHED` | 两端 TCP 连接已经建立 | 当前存在一条已建立的 TCP 连接 |

监听是正常的网络概念。这里的“监听”表示等待连接，不等于有人在窃听，也不能直接判断为被攻击。

服务器可以同时存在监听记录和多条已建立连接：

```text
服务端口继续 LISTENING
├─ 与客户端 A 的连接：ESTABLISHED
└─ 与客户端 B 的连接：ESTABLISHED
```

`ESTABLISHED` 不代表一定正在大量传输数据，也不代表通信一定安全；它描述的是 TCP 连接状态。

UDP 没有 TCP 这套连接状态，不能要求 UDP 行也出现 LISTENING / ESTABLISHED。

# 三、0.0.0.0 与 127.0.0.1

## 1. 0.0.0.0：本机所有 IPv4 接口

在本地监听地址中看到：

```text
0.0.0.0:8080
```

可以理解为：程序在本机所有 IPv4 接口的 8080 端口等待连接，而没有只限定某一个本机 IPv4 地址。

这是监听范围的表示，不是一台远程主机的真实地址。它只涉及 IPv4；IPv6 监听范围另看相应记录。

外部设备能否连进来，还取决于防火墙、路由、NAT 等条件。监听所有接口，不等于已向整个互联网开放。

微软对通配地址绑定的说明见 [Winsock bind](https://learn.microsoft.com/en-us/windows/win32/api/winsock/nf-winsock-bind)。

## 2. 127.0.0.1：本机回环地址

回环地址用于本机访问本机，例如：

```text
本机客户端 → 127.0.0.1:8080 → 本机服务
```

通信在本机内部完成，不需要通过局域网去找另一台电脑。

如果服务只监听 `127.0.0.1:8080`，其他电脑不能直接通过本机的局域网 IP 连接这个监听入口。

每台电脑的 `127.0.0.1` 都指向它自己。另一台电脑访问 `127.0.0.1`，访问的是它自己。

## 3. 同一个地址要结合位置理解

```text
本地监听栏中的 0.0.0.0:8080 → 所有本机 IPv4 接口
监听行远程栏中的 0.0.0.0:0 → 尚无具体连接对端
路由表中的 0.0.0.0/0      → 默认路由
127.0.0.1                → 本机回环地址
```

不要把上一篇路由表里的 `0.0.0.0/0` 与这里的监听地址混成一个概念。

# 四、netstat -ano 基础阅读

## 1. 命令、作用与参数

在 Windows PowerShell 或命令提示符中使用：

```powershell
netstat -ano
```

作用：查看本机 TCP 连接、TCP 监听端口和 UDP 端点，并显示相关 PID。它把“网络通信”与“哪个进程在使用这个入口”连接起来。

| 参数 | 含义 | 为什么用 |
|---|---|---|
| `-a` | 显示所有活动 TCP 连接及 TCP / UDP 监听端口 | 同时看连接和等待通信的入口 |
| `-n` | 用数字显示 IP 和端口，不解析名称 | 直接读出地址和端口号 |
| `-o` | 显示 PID | 后续查找所属进程 |

参数与列含义参考 [微软 netstat 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netstat)。

## 2. 预期输出与列含义

下面是简化示例；自己的电脑上具体地址、端口、PID 和记录数量会不同。

```text
Proto  Local Address          Foreign Address        State          PID
TCP    0.0.0.0:8080           0.0.0.0:0              LISTENING      4321
TCP    127.0.0.1:9000         0.0.0.0:0              LISTENING      5678
TCP    192.168.1.20:53000     203.0.113.80:443        ESTABLISHED    8765
```

| 列 | 阅读方式 |
|---|---|
| `Proto` | 使用 TCP 还是 UDP |
| `Local Address` | 执行命令这台主机的 IP:端口 |
| `Foreign Address` | 连接对端的 IP:端口；监听行尚无具体对端 |
| `State` | TCP 状态 |
| `PID` | 使用该连接或端点的进程编号 |

Local / Foreign 是以执行命令的主机为观察点，不等于永久固定的客户端 / 服务器。

## 3. 逐行解释

第一行：PID 4321 的进程在本机所有 IPv4 接口的 TCP 8080 端口等待连接。远程栏 `0.0.0.0:0` 不表示已经连上了一台叫 0.0.0.0 的机器。

第二行：PID 5678 的进程只在本机回环地址的 TCP 9000 端口监听。

第三行：本机 `192.168.1.20:53000` 与对端 `203.0.113.80:443` 之间存在已建立的 TCP 连接，所属 PID 为 8765。

第三行符合常见的客户端访问 HTTPS 服务的形式，但服务类型仍需结合程序和通信上下文确认，不能仅凭端口号下结论。

## 4. 阅读顺序与常见错误

```text
先看协议
↓
再看本地 IP:端口与远程 IP:端口
↓
判断 TCP 状态
↓
记录 PID，继续查进程
```

- 没有 `-n` 时可能显示名称，阅读时容易把名称与数字地址混淆。
- PID 不是端口号；端口识别通信入口，PID 识别具体进程实例。
- UDP 行通常没有 TCP 的 State 列值，远程栏也可能是 `*:*`。
- 一次输出是当前状态的快照；连接可能随后断开，进程也可能退出。
- 同一个 PID 可以对应多条网络记录，不能把“一条记录”当作“一个独立进程”。

# 五、今日必须掌握与易混淆点

1. 客户端有自己的端口，常见形式是“客户端 IP:临时端口 ↔ 服务器 IP:服务端口”。
2. LISTENING 表示等待连接；ESTABLISHED 表示 TCP 连接已经建立。
3. 本地监听地址 0.0.0.0 表示所有本机 IPv4 接口，127.0.0.1 表示本机回环地址。
4. 监听所有接口不等于互联网一定能访问；连接已建立也不等于通信一定安全。
5. netstat -ano 的 PID 是追查所属进程的入口，不能只凭进程名、端口或状态判断异常。

复习时先口头解释一条 LISTENING 和一条 ESTABLISHED 记录，再沿 PID 说明下一步如何找到进程。

# 六、与 Windows 主机安全的衔接

本节仍归属于 Part 01 · 网络基础补齐。下面这条链把网络状态连接到此前的 Windows 进程知识：

```text
网络连接
↓
PID
↓
进程名
↓
路径（ExecutablePath）
↓
PPID / 父进程（ParentProcessId）
↓
CommandLine
```

| 信息 | 回答的问题 |
|---|---|
| 网络连接 | 本机哪个入口在监听，或与哪个对端连接？ |
| PID / ProcessId | 这条网络记录属于哪个具体进程？ |
| 进程名 / Name | 正在运行的程序叫什么？ |
| ExecutablePath | 对应程序文件实际在哪里？ |
| PPID / ParentProcessId | 哪个进程创建了它？ |
| CommandLine | 它启动时使用了什么命令和参数？ |

## 1. 按 PID 查看进程

例如 netstat 显示 PID 为 8765，可以查询：

```powershell
Get-Process -Id 8765

Get-CimInstance Win32_Process -Filter 'ProcessId = 8765' |
Select-Object Name, ProcessId, ExecutablePath, ParentProcessId, CommandLine |
Format-List
```

把 8765 换成当前输出中的真实 PID。第一条先找进程名，第二条继续看路径、父进程编号和启动命令；Format-List 便于阅读较长字段。

预期得到该进程的信息；如果没有结果或报找不到进程，可能是它已经退出。部分字段也可能因权限或进程限制无法读取，空白本身不能证明异常。

PID 会被重新使用，PPID 指向的父进程也可能已经退出。前后两次查询需要结合观察时间，必要时再核对创建时间，避免把同一个数字当作永久身份。

## 2. CommandLine 不是全部行为记录

```text
进程名：python.exe
CommandLine：python test.py
```

这说明进程启动时让 Python 执行 test.py。

```text
powershell.exe -File C:\Scripts\backup.ps1
```

这提供了启动时执行 backup.ps1 的上下文。但启动之后读取了哪些文件、建立了哪些连接、修改了哪些注册表项，不会全部写进 CommandLine，需要结合其他日志和行为信息判断。

> CommandLine = 怎么启动、启动时传了什么参数；不是进程一生的完整行为记录。

字段定义和 PID / PPID 的使用边界参考 [微软 Win32_Process 文档](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process)。
