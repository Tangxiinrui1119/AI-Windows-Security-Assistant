# 一、学习目标

完成入门阶段后，应该能够：

1. 看懂常见 HTTP 请求与响应，理解浏览器、服务器和数据库之间的基本交互。
2. 使用浏览器开发者工具和 Burp Suite 查看、分析授权实验环境中的请求。
3. 理解常见 Web 漏洞的成因、影响和防御方法。
4. 能够阅读题目描述、观察应用行为、提出假设并记录验证过程。
5. 能够阅读 Writeup，判断解题思路是否真正理解，而不是只记住答案。
6. 为 VulnBot / 烛阴的 Web CTF 测试提供基本的技术判断和测试记录。

[!IMPORTANT]
本阶段的目标不是背诵 payload 或依赖自动化工具，而是理解 Web 应用为什么会出现安全问题、如何用证据验证判断，以及开发者如何修复问题。

# 三、第一部分：Web 基础

## 1. Web 应用的基本结构

典型 Web 应用可以抽象为：

    浏览器（客户端）
        ↓ HTTP 请求
    Web 服务器 / 应用后端
        ↓ 查询或写入
    数据库 / 文件 / 其他服务
        ↓ 处理结果
    Web 服务器
        ↓ HTTP 响应
    浏览器渲染页面

需要理解：

- 浏览器负责发送请求、执行前端代码和展示页面。
- 服务端负责业务逻辑、身份校验、权限判断和数据处理。
- 数据库负责持久化数据。
- 前端的限制不能替代服务端的安全检查。

## 2. HTTP 请求与响应

重点概念：

| 概念 | 含义 |
|---|---|
| URL | 资源定位地址 |
| Method | 请求方法，如 GET、POST |
| Status Code | 响应状态码，如 200、302、403、404、500 |
| Header | 请求或响应的元数据 |
| Body | 请求或响应携带的数据 |
| Content-Type | 描述消息体的数据类型 |
| Host | 请求目标主机信息 |
| Cookie | 浏览器向站点携带的状态数据 |

需要掌握的请求方法：

- GET：通常用于获取资源。
- POST：通常用于提交数据或触发处理。
- PUT / PATCH：常用于更新资源。
- DELETE：常用于删除资源。

不要只记方法名称，要结合请求和响应理解服务端实际做了什么。

## 3. 浏览器基础

至少认识：

- HTML：网页结构。
- CSS：页面样式。
- JavaScript：浏览器端逻辑。
- DOM：浏览器对页面结构形成的对象模型。
- Form：表单提交。
- JSON：常见的数据交换格式。
- URL Encoding：URL 参数编码。

浏览器开发者工具重点看：

- Network：请求、响应、状态码、耗时。
- Elements：页面 HTML / DOM。
- Console：前端错误与调试信息。
- Application / Storage：Cookie、本地存储等。

# 四、第二部分：身份认证、会话与数据库

## 1. Authentication 与 Authorization

这两个概念必须分清：

| 概念 | 核心问题 | 例子 |
|---|---|---|
| Authentication（认证） | 你是谁？ | 用户名、密码、登录状态 |
| Authorization（授权） | 你能做什么？ | 普通用户能否查看管理员数据 |

登录成功不代表用户有权访问所有资源。

## 2. Cookie、Session、Token

- Cookie：浏览器保存并按规则随请求发送的数据。
- Session：服务端维护的会话状态，常通过会话标识与客户端关联。
- Token：用于表示或传递认证、授权相关信息的凭证。
- JWT：一种具有特定结构的 Token 格式。

重点理解：

1. 登录后浏览器如何保持状态？
2. 服务端如何识别当前用户？
3. 退出登录后会话如何失效？
4. 服务端如何判断当前用户是否有权访问某个对象？

## 3. SQL 与 MySQL

- SQL：结构化查询语言。
- MySQL：关系型数据库管理系统。
- SQL 注入的根本问题：应用把不可信输入不安全地拼接进 SQL 查询，导致数据和指令边界被破坏。

先复习：

- SELECT、INSERT、UPDATE、DELETE。
- WHERE 条件。
- ORDER BY。
- JOIN 的基本作用。
- 主键、外键。
- 参数化查询。

防御重点：使用参数化查询 / 预编译语句，不依赖简单的字符串过滤。

## 4. 常见身份与访问控制问题

重点理解：

- 弱身份认证。
- 会话管理不当。
- 缺少服务端权限校验。
- IDOR（不安全的直接对象引用）。
- 水平越权与垂直越权。

核心防御原则：每次访问资源时，服务端都要基于当前身份重新校验该用户对目标对象的权限。

# 五、第三部分：常见 Web 漏洞知识地图

以下内容先掌握“是什么、为什么发生、如何识别风险、如何防御”。实操只在自己搭建的环境、公开教学靶场或明确授权的 CTF 环境中进行。

| 漏洞 | 核心成因 | 应重点理解的内容 | 防御方向 |
|---|---|---|---|
| SQL 注入 | 不可信输入影响 SQL 语句结构 | SQL 查询逻辑、参数化查询 | 参数化查询、最小数据库权限 |
| XSS | 不可信内容被浏览器当作脚本执行 | HTML / JS 上下文、输出编码 | 上下文编码、可信模板、CSP 作为纵深防御 |
| CSRF | 浏览器自动携带凭证，服务端缺少请求来源 / 意图校验 | Cookie、会话、跨站请求 | CSRF Token、SameSite、敏感操作二次校验 |
| SSRF | 服务端代替用户访问不可信目标 | 服务端网络请求、信任边界 | 目标白名单、出站访问控制、网络隔离 |
| 文件上传风险 | 文件类型、内容、存储或访问策略不当 | 文件元数据、内容校验、存储位置 | 白名单、内容检查、随机命名、禁止执行 |
| 路径遍历 | 用户输入影响文件路径且缺少边界校验 | 路径规范化、目录边界 | 固定目录、规范化后校验、最小权限 |
| XXE | XML 解析器不安全处理外部实体 | XML、实体、解析器配置 | 禁用不必要的外部实体与 DTD |
| SSTI | 用户输入进入服务端模板表达式上下文 | 模板引擎与数据边界 | 不把用户输入当模板执行 |
| 命令注入 | 用户输入影响系统命令执行 | 应用与操作系统边界 | 避免拼接命令、使用安全 API、严格校验 |
| 不安全反序列化 | 将不可信数据还原为对象并触发危险行为 | 序列化、对象构造、信任边界 | 不反序列化不可信数据、完整性校验 |
| JWT / API 风险 | Token 校验、接口权限或业务约束不当 | 签名、有效期、受众、服务端授权 | 正确校验 Token，逐接口执行权限检查 |
| 业务逻辑漏洞 | 程序只验证表面流程，遗漏业务约束 | 状态转换、价格、次数、角色与流程 | 服务端统一执行业务规则 |

## 1. SQL 注入（SQL Injection）

需要掌握：

- SQL 查询由哪些部分组成。
- 用户输入如何进入数据库查询。
- 为什么字符串拼接可能破坏指令与数据的边界。
- 参数化查询如何解决这一类问题。
- 数据库账户最小权限原则。

## 2. XSS（Cross-Site Scripting）

常见分类：

- 反射型 XSS。
- 存储型 XSS。
- DOM 型 XSS。

需要理解：

- 浏览器如何解析 HTML。
- JavaScript 如何操作 DOM。
- 为什么不同输出上下文需要不同编码。
- 为什么不能把过滤几个字符当成完整防御。

## 3. 文件上传

需要理解：

- 文件扩展名与真实内容不一定一致。
- Content-Type 不能单独作为可信依据。
- 文件名、存储位置和访问权限都影响风险。
- 上传目录不应允许不可信文件被当作可执行程序运行。

## 4. SSRF

需要理解：

- 为什么服务端会主动发起网络请求。
- 用户提供的 URL 为什么会成为信任边界问题。
- 为什么只检查 URL 字符串可能不够。
- 如何通过出站网络策略和目标白名单降低风险。

## 5. 访问控制与 IDOR

需要理解：

- 用户能登录不代表可以访问任意对象。
- 资源 ID 不应被当作权限凭证。
- 服务端必须验证当前用户与目标资源之间的授权关系。

# 六、第四部分：Burp Suite 与辅助工具

## 1. Burp Suite

官方入口：https://portswigger.net/burp

先认识以下功能：

| 功能 | 用途 |
|---|---|
| Proxy | 观察浏览器与服务端之间的 HTTP 流量 |
| HTTP history | 查看请求与响应历史 |
| Repeater | 在授权实验中重复发送和比较请求 |
| Decoder | 理解常见编码格式 |
| Inspector | 结构化查看请求与响应内容 |
| Intruder | 自动化请求测试功能，初学阶段只了解用途 |

第一阶段重点是 Proxy、HTTP history 和 Repeater。

## 2. 浏览器开发者工具

优先熟悉 Network、Elements、Console、Application。

很多初级 Web 题目只要先把页面加载了什么资源、发出了什么请求、浏览器保存了什么状态看清楚，就能建立正确的问题模型。

## 3. Nmap

Nmap 属于网络探测和服务识别工具，不是 Web 漏洞分析的替代品。

目前只需了解它的定位，后续学习信息收集时再系统学习。

# 八、每天 30～60 分钟的学习方法

建议采用一个固定循环：

| 时间 | 内容 |
|---|---|

# 九、VulnBot / 烛阴 Web 测试的题目选择建议

测试 Agent 时，不建议只选“难题”。

如果全部使用高难度题目，失败后很难判断究竟是基础能力不足、工具使用问题，还是复杂漏洞组合导致的。

建议一个小型测试批次包含：

1. 一道基础题：检查基本 Web 认知。
2. 一道中等题：检查规划和证据分析。
3. 一道较难题：检查复杂场景下的稳定性。

每道题尽量记录：

- 题目来源与版本。
- 官方或可信参考解法。
- 靶场启动方式和环境信息。
- Agent 的输入任务。
- 运行日志与耗时。
- 是否完成、结果是否可验证。
- 失败发生在哪个环节。
- 人工复核结论。

不要只记录最终 Flag 是否正确，还要判断 Agent 是否真的理解了问题。

所有测试仅限自己搭建、公开 CTF 或明确授权的靶场；不要把课程方法用于真实网站或未经授权的目标。

# 十、阶段性检查标准

完成第一轮 Web 入门后，检查自己是否能够：

- [ ] 解释一次 HTTP 请求与响应的基本过程。
- [ ] 区分 Cookie、Session、Token。
- [ ] 区分认证和授权。
- [ ] 解释 SQL 注入的根本成因及参数化查询。
- [ ] 区分反射型、存储型和 DOM 型 XSS。
- [ ] 解释 CSRF、SSRF 和越权的基本原理。
- [ ] 使用 Burp 查看授权实验环境中的请求与响应。
- [ ] 独立阅读一道入门 Web CTF 题目的题面。
- [ ] 写出一份包含原理、证据和防御建议的 Writeup。

达到这些要求后，再进入更复杂的漏洞组合和源码分析。
